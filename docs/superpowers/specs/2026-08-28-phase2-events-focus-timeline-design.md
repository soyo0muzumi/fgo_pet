# FGO Pet Phase 2：事件、专注与今日时间线设计

日期：2026-08-28

状态：待用户书面审阅

基线：Phase 1 `main`，工程交接状态为 `ready`，正式发行仍为 `deferred`

## 1. 目标与原则

Phase 2 在 Phase 1 已完成的 WPF 桌宠壳上增量实现统一事件、可恢复番茄钟、今日时间线和轻量羁绊等级。它不重建窗口、画像、附着面板或角色包运行时，也不提前实现 Phase 3 的 LLM 对话和 Phase 4 的 Agent 接入。

设计原则：

- 保持 Phase 1 的画像、窗口、附着几何、美术风格、DPI 处理和资源包行为不变；
- 只在现有扩展点增加 Phase 2 状态与数据流；
- 运行时业务数据从本阶段起统一使用 SQLite，并建立后续阶段沿用的数据分层；
- 计时、时间线和羁绊结算必须可恢复、可追溯且只执行一次；
- 角色化台词属于角色包，主程序只提供无角色中性回退；
- 以完成 Phase 2 的本地闭环为目标，不引入任务管理和复杂统计。

## 2. 范围

### 2.1 包含

- 番茄钟预设：`25/5 × 4`、`50/10 × 2` 和自定义；
- 开始、暂停、继续、主动退出、专注完成、休息和循环完成；
- 应用关闭或异常终止后的暂停恢复；
- 番茄事件的统一内部模型、幂等处理和最小优先级规则；
- 今日有效专注、完成/中断/循环/羁绊升级时间线；
- 每个角色独立累计的羁绊等级；
- 角色包可选的 `dialogue/` 本地事件台词合同；
- 现有附着面板新增“专注”和“今日”伸展内容；
- `TODO` 入口保留为空扩展面，等待未来 Codex 或其他 Agent；
- SQLite schema、迁移、事务和测试门禁。

### 2.2 不包含

- Todo 数据模型、编辑、提醒、完成逻辑或持久化；
- LLM 对话、Prompt、记忆和剧情知识检索；
- Codex/Agent 事件桥、离线队列和跳转；
- 应用感知；
- 收藏、礼装、复杂成就或虚拟经济；
- 图表、搜索、导出和高级统计；
- 角色包内的脚本或其他可执行逻辑；
- 程序包或角色包正式发行。

## 3. Phase 1 继承合同

以下能力原样继承：

- .NET 8 WPF 应用壳与 Core / Infrastructure / App 分层；
- 双层画像、表情回退、Alpha 命中、拖动、缩放和边缘约束；
- 面板的深海军蓝半透明背景、青色边框、青/洋红强调、切角轮廓和中英文字体回退；
- 面板覆盖人物腰部以下、位于画像上层并从 manifest `panel_anchor` 附着；
- 面板宽度受控在现有 `220–340 DIP` 区间，伸展高度不超过工作区 60%；
- 人物位置不因面板伸展、缩回、内容增长、DPI 或移动而改变；
- 单击人物开合面板、`Esc` 分级返回、伸展状态空闲后回到 Compact；
- 从者包安装、扫描、切换、卸载和版本回退；
- 设置、窗口位置和选择状态的版本化 JSON 持久化。

Phase 2 不创建第二个计时窗口或平行面板。所有新内容均进入现有附着面板。

## 4. 附着面板与信息架构

### 4.1 状态

在现有状态机上增量扩展：

```text
Collapsed
Compact
ExpandedFocus
ExpandedToday
ExpandedTodo
ExpandedDialogue
```

“Expanded”表示同一个附着面板保持标题栏、宽度和锚点，向纵向伸展并在正文区域显示详细内容；它不是独立页面、窗口或替换表面。

### 4.2 栏目

Compact 标题栏固定为：

```text
专注 | 今日 | TODO | 对话
```

- `专注`：伸展番茄预设与控制内容；
- `今日`：伸展当前角色羁绊与今日时间线；
- `TODO`：保留未来 Agent 接口，只显示中性空状态；
- `对话`：保留 Phase 1 边界，Phase 2 不接入 LLM。

不显示“收起”栏目。单击人物关闭整个面板；`Esc` 从伸展状态回到 Compact，再次按下关闭。再次点击当前栏目缩回 Compact，点击其他栏目直接切换对应伸展内容。

伸展状态在鼠标位于人物/面板之外且 30 秒无交互时回到 Compact；编辑自定义计时参数期间不自动缩回。

### 4.3 Compact 正文

番茄钟空闲时保留本地角色短句。计时开始后，同一正文区域切换为迷你计时状态，不增加 Compact 高度：

```text
专注中  24:18  第 1/4 轮    暂停 | 退出
已暂停  24:18               继续 | 退出
休息中  04:32               暂停 | 退出
```

操作继续使用现有青/洋红文字风格，不改成实心大按钮。完成时短暂显示有效专注时间和羁绊进度，随后进入休息计时或恢复角色短句。

### 4.4 专注伸展内容

- 预设：`25/5 × 4`、`50/10 × 2`、`自定义`；
- 提供开始、暂停/继续和退出；
- 主动退出需要一次轻量确认；
- 不包含任务名称、Todo 关联、标签或项目字段。

三个方案使用符合现有终端风格的文字选项，不使用独立卡片或新窗口。选择“自定义”后，在同一伸展内容区显示：

```text
专注时长       [ − ]  35 分钟  [ ＋ ]
休息时长       [ − ]  10 分钟  [ ＋ ]
循环轮数       [ − ]   3 轮    [ ＋ ]

预计总时长：2 小时 5 分钟

              [ 开始专注 ]
```

自定义参数合同：

- 专注时长范围为 `5–180` 分钟，步进 5 分钟；
- 休息时长范围为 `1–60` 分钟，步进 5 分钟；
- 循环轮数范围为 `1–12`，步进 1；
- 数值支持 `− / ＋` 调整，也允许点击数值后使用键盘输入；
- 非法输入在字段附近显示洋红色提示，并禁用“开始专注”；
- 预计总时长为全部专注阶段加阶段间休息，最后一轮完成后不计算休息；
- 用户最后一次有效自定义值自动保存并在下次选择时恢复；
- 首版不支持给方案命名或保存多个自定义方案；
- 开始后面板缩回 Compact，并在 Compact 正文显示迷你计时状态；
- 高度不足时详细内容允许垂直滚动，标题栏和主要开始操作保持可达。

### 4.5 今日伸展内容

顶部显示当前角色的羁绊等级、距下一级所需有效专注时间和今日有效专注总时长。下方只读显示：

- 专注阶段自然完成；
- 用户主动中断；
- 完整循环完成；
- 羁绊等级提升。

暂停、继续、休息开始和休息结束不进入时间线。首版不提供历史日期切换、筛选、图表、搜索或编辑。

## 5. 番茄钟领域模型

### 5.1 状态机

```text
Idle
  └─ Start → Focusing
Focusing
  ├─ Pause → PausedFocus
  ├─ Stop → Idle
  └─ 到时 → Breaking / Completed
PausedFocus
  ├─ Resume → Focusing
  └─ Stop → Idle
Breaking
  ├─ Pause → PausedBreak
  ├─ Stop → Idle
  └─ 到时 → Focusing / Completed
PausedBreak
  ├─ Resume → Breaking
  └─ Stop → Idle
Completed
  └─ Acknowledge → Idle
```

状态机属于 Core，不引用 WPF、SQLite、角色包文件或静态系统时间。时间由 `TimeProvider` 注入。WPF `DispatcherTimer` 只刷新显示，不作为业务真相。

### 5.2 计时与恢复

- 当前进程内使用单调时间计算剩余秒数，避免 Dispatcher tick 延迟累计误差；
- 持久化统一使用整数秒；
- 状态变化时立即保存；运行期间按受控间隔保存剩余时间快照；正常退出时再次保存；
- 应用关闭、崩溃或系统重启期间不推进计时；
- `Focusing` 恢复为 `PausedFocus`，`Breaking` 恢复为 `PausedBreak`；
- 恢复采用最近一次可靠快照，不补算离线时间，不自动跨阶段结算；
- 只有前台自然完成的专注阶段计入有效专注；
- 主动退出形成一次中断记录，不计有效专注，不增加或扣除羁绊。

### 5.3 阶段角色归属

专注阶段开始时记录稳定角色 ID。本阶段自然完成后，有效专注时间归属该角色；阶段中途切换角色不改变归属。外观切换不视为更换角色。

## 6. 统一事件与投影

### 6.1 基础字段

每个运行时事件包含：

- 稳定、全局唯一的事件 ID；
- 会话 ID；
- 小写稳定事件类型；
- UTC 发生时间；
- 阶段序号与循环序号；
- 阶段角色 ID；
- 实际时长秒数；
- schema 版本；
- 可选的版本化 JSON payload。

Phase 2 事件类型：

```text
focus_started
focus_paused
focus_resumed
focus_completed
focus_stopped
break_started
break_paused
break_resumed
break_completed
cycle_completed
bond_level_up
```

### 6.2 最小调度规则

- 阶段完成反馈可以覆盖普通 Compact 短句；
- 专注运行期间抑制无关的普通反馈；
- 同一阶段完成事件只能处理一次；
- 本地角色台词执行近期去重；
- Phase 2 不实现多来源复杂队列、事件合并和完整 P0–P4 调度器，但保留以后扩展所需的来源与优先级字段。

### 6.3 时间线投影

内部事件保持完整，但只有 `focus_completed`、`focus_stopped`、`cycle_completed` 和 `bond_level_up` 投影为今日时间线条目。

## 7. 角色独立羁绊等级

### 7.1 累计规则

- 每个稳定角色 ID 独立累计终身有效专注秒数；
- 中断、暂停和休息不增减；
- 不设每日积分上限，所有自然完成的有效专注时间均累计；
- 角色包卸载后保留羁绊数据，重新安装相同角色 ID 后恢复；
- 当前外观不影响羁绊归属。

### 7.2 等级曲线

全角色使用主程序统一曲线，最高 `Lv.10`：

| 升级 | 新增有效专注 | 累计有效专注 |
|---|---:|---:|
| Lv.1 → 2 | 1 小时 | 1 小时 |
| Lv.2 → 3 | 2 小时 | 3 小时 |
| Lv.3 → 4 | 3 小时 | 6 小时 |
| Lv.4 → 5 | 4 小时 | 10 小时 |
| Lv.5 → 6 | 5 小时 | 15 小时 |
| Lv.6 → 7 | 6 小时 | 21 小时 |
| Lv.7 → 8 | 7 小时 | 28 小时 |
| Lv.8 → 9 | 8 小时 | 36 小时 |
| Lv.9 → 10 | 9 小时 | 45 小时 |

达到 Lv.10 后继续统计总有效专注时间，但不再升级。

### 7.3 可替换策略

业务代码通过内部扩展接口获取等级，不写死阈值：

```csharp
public interface IBondProgressionPolicy
{
    string Version { get; }
    int MaxLevel { get; }
    BondProgress Evaluate(long lifetimeFocusSeconds, int achievedLevel);
}
```

SQLite 保存累计有效秒数、已达到的最高等级和策略版本。后续调整曲线时可重新计算进度，但已达到等级不回退。该 hook 是应用内部 C# 接口，不允许角色包提供可执行实现；角色包只能提供等级反馈台词。

## 8. 数据分层与 SQLite 合同

### 8.1 长期分层

| 数据类别 | 存储 | 示例 |
|---|---|---|
| 运行时业务数据 | SQLite | Phase 2 事件、番茄、时间线、羁绊；后续聊天、记忆、收藏 |
| 简单用户偏好 | 版本化 JSON | 窗口、缩放、隐私选项、模型名称 |
| 敏感凭据 | Windows Credential Manager | Phase 3 API Key |
| 声明式角色内容 | 角色包文件 | 外观、台词、Persona、知识索引 |
| 可重建内容 | 缓存或独立内容数据库 | 缩略图、响应缓存、剧情全文索引 |

后续阶段原则上沿用同一个本地 SQLite 运行库并按领域分表。随角色包重建的剧情全文索引可以使用独立内容数据库，不与用户运行数据混合。

### 8.2 类型约定

- 跨系统主键使用稳定字符串 ID，不以自增号作为业务标识；
- 时间统一保存为 UTC，展示时转换为本地时区；
- 时长统一使用整数秒；
- 布尔值使用 `0/1`；
- 枚举保存稳定小写字符串，不保存 C# 枚举序号；
- 可扩展 payload 使用带 schema 版本的 JSON，核心查询字段使用正式列；
- schema 通过显式、顺序迁移升级，启动时不得直接重建用户数据库。

### 8.3 表职责

```text
schema_migrations   已应用迁移
focus_presets       内置与用户自定义预设
focus_sessions      当前/历史会话、阶段和恢复快照
runtime_events      统一事件及幂等键
timeline_entries    有回顾价值的只读投影
servant_bonds       每角色累计秒数、最高等级和策略版本
bond_ledger         每笔有效专注来源与增量
```

### 8.4 完成事务

专注阶段自然完成时，在一个 SQLite 事务内：

1. 插入唯一 `focus_completed` 事件；
2. 更新会话到休息或完成状态；
3. 插入今日时间线条目；
4. 为阶段归属角色增加有效秒数；
5. 以 `source_event_id` 唯一键插入羁绊账本；
6. 使用当前 `IBondProgressionPolicy` 计算等级；
7. 如升级，更新最高等级并写入 `bond_level_up` 事件与时间线；
8. 提交事务。

任一步失败整体回滚。重复处理相同事件时由事件和账本唯一约束阻止重复累计。

## 9. 角色包 `dialogue/` 合同

### 9.1 结构

```text
dialogue/
├─ manifest.json
└─ zh-CN.json
```

`dialogue/` 是可选能力。缺失时不影响画像、包扫描或番茄钟。

`manifest.json`：

```json
{
  "schema_version": 1,
  "default_locale": "zh-CN",
  "localizations": {
    "zh-CN": "zh-CN.json"
  }
}
```

本地化文件：

```json
{
  "focus_started": [
    {
      "id": "focus_started_01",
      "text": "准备好了的话，我们就开始吧，前辈。",
      "expression": "focused",
      "weight": 1
    }
  ],
  "focus_completed": [],
  "focus_stopped": [],
  "break_started": [],
  "cycle_completed": [],
  "bond_level_up": []
}
```

### 9.2 安全与回退

- `id` 在角色包版本内稳定，用于近期去重；
- `text` 为有长度限制的纯文本，不解释 Markdown、命令或链接；
- `expression` 只能使用应用支持的核心表情语义；
- `weight` 只影响同事件候选选择；
- 不允许脚本、条件表达式、Prompt、文件路径、权限或工具调用；
- 角色内容不能改变计时、事件优先级、结算、等级曲线或持久化；
- 应用语言缺失时回退角色包默认语言，再回退主程序中性提示；
- 目录缺失、事件键为空或单条内容无效时使用中性提示；
- 表情无效时使用默认表情；
- 单个 `dialogue/` 错误只禁用该能力，不影响角色包其他内容。

中性系统提示只陈述状态，如“专注已开始”“本轮专注已完成”，不得冒充当前角色说话。

## 10. 组件与数据流

Phase 2 延续现有项目，不创建平行架构：

```text
现有 DesktopAppShell
        ↓ 启动恢复
新增 FocusSessionService
        ↓ 领域事件
新增 EventCoordinator
        ├─ SQLite 事务与投影
        ├─ 更新现有 AttachedPanelViewModel
        └─ 通过现有 IPortraitController 请求表情
```

建议新增的职责边界：

- Core/Focus：纯状态机、命令结果和预设验证；
- Core/Events：事件合同、最小调度与时间线投影规则；
- Core/Bond：角色归属和 `IBondProgressionPolicy`；
- Infrastructure/Persistence：SQLite 连接、迁移和事务；
- Infrastructure/Packs：`dialogue/` 读取与验证；
- App/Focus：UI tick、命令编排和恢复；
- App/Feedback：角色台词选择、近期去重和中性回退；
- App/Panels：在现有 View/ViewModel 上增加伸展状态和真实数据流。

## 11. 错误处理

- SQLite 首次启动自动创建；升级仅执行显式迁移；
- 迁移失败时保留原数据库，不删除或重建；桌宠以 Phase 1 能力启动并禁用 Phase 2；
- 番茄状态保存失败时立即暂停并显示中性错误，避免不可可靠结算的后台运行；
- `dialogue/` 损坏只禁用对应角色的事件台词；
- 重复事件和重复账本来源按幂等成功处理，不重复展示或累计；
- 当前角色包卸载不删除其羁绊和历史；
- 时间线查询失败不影响当前计时，但显示可恢复的中性错误状态。

## 12. 验证

### 12.1 自动化

- Core：全部番茄状态转换、阶段推进、暂停恢复、预设边界和单调时间计算；
- Core：角色归属、有效秒数累计、统一曲线、Lv.10 上限和等级不回退；
- Core：事件去重、最小反馈优先级、时间线投影和中断不结算；
- Infrastructure：数据库创建、顺序迁移、事务回滚、事件/账本唯一约束；
- Infrastructure：`dialogue/` schema、语言回退、纯文本限制和局部失效；
- App：Compact 空闲/运行切换、四栏目伸展/缩回、Todo 空状态和对话隔离；

- 恢复：专注、休息和暂停状态在重启后均恢复为对应暂停状态；
- 回归：Phase 1 现有 222 项自动化继续通过。

### 12.2 实机

- `25/5 × 4`、`50/10 × 2` 和自定义预设各完成一次关键流程；
- 验证暂停、继续、主动退出、正常退出和异常恢复；
- 验证 25 分钟与 50 分钟完成后的有效时间、时间线和羁绊进度；
- 使用两个角色验证独立累计，并验证阶段中切换角色不改变归属；
- 验证 Compact 与四个伸展状态不移动人物、不破坏拖动和命中；
- 将 150%、200% 和混合 DPI 结果与 Phase 1 遗留矩阵一并归档。

## 13. 实施分批

1. SQLite 基础、迁移、统一事件存储和测试 fixture；
2. 番茄状态机、预设、快照恢复和完成事务；
3. 每角色羁绊等级与今日时间线；
4. 在现有附着面板上增加四栏目、Compact 计时状态和伸展内容；
5. 角色包 `dialogue/` 合同、反馈选择、表情倾向和中性回退；
6. 全量自动化、Windows 实机复核和 Phase 2 交接报告。

每一批都必须保持 Phase 1 测试通过。任何要求改变画像窗口、面板附着几何或资源包安装安全边界的隐藏复杂度，都必须暂停并单独评审。

## 14. 完成标准

- 用户可使用两个内置预设和受限自定义预设完成、暂停、继续或退出番茄循环；
- 应用重启后活动阶段可靠恢复为暂停，且不累计离线时间；
- 专注完成、中断、循环完成和羁绊升级只记录一次；
- 当前角色按自然完成的有效专注时间独立累计羁绊等级；
- “今日”伸展内容能显示当前角色等级、今日有效专注和最小时间线；
- 当前角色包可提供本地事件台词和表情倾向，缺失或无效时安全回退；
- Todo 保持空扩展面，Phase 3/4 能力没有被提前实现；
- Phase 1 的视觉、交互、窗口与包运行时合同保持成立；
- 自动化与目标 Windows 实机矩阵形成可复核证据。
