# FGO Pet Phase 0 渲染验证设计

日期：2026-08-27

## 目标

Phase 0 通过一次性 .NET 8 WPF 探针，为 Windows 11 桌宠选择画像渲染器与透明窗口合成模式，并沉淀 Phase 1 可重新实现的资源、合成、DPI 和诊断契约。

本阶段不是正式桌宠工程。探针代码保持在 `spikes/rendering`，不得未经独立评审直接复制进 Phase 1。Phase 0 的可复用产物是经过验证的接口、参数、测试口径和技术决策，而不是 spike 实现本身。

## 已确认的产品基线

- 目标系统为 Windows 11。
- 人物默认按源合成画布统一缩放至 60%；另测试 50% 与 75%。
- Windows 显示缩放覆盖 100%、125% 与 150%。
- 当前没有混合 DPI 双显示器环境；跨显示器移动标记为 `not observed`，不阻塞 Phase 0，并列为 Phase 1 发布前补测项。
- 默认优先使用原生 WPF 渲染；SkiaSharp 只有证明明显画质收益时才引入。
- 默认优先使用常规 WPF 透明窗口；DWM 模式只有证明明确性能或稳定性收益时才采用。
- 桌宠保留完整全身构图；对话或 Todo 面板可以临时覆盖腰部以下，关闭面板后恢复完整人物。

## 阶段边界

### 包含

1. 修复并重新验证现有透明素材处理。
2. 定义身体底图与表情差分层的组合契约。
3. 校准全部 28 个表情差分层。
4. 对比 WPF Image 与 SkiaSharp 两种画像渲染器。
5. 对比常规 WPF 与 DWM 两种透明窗口合成模式。
6. 验证统一缩放、DPI 对齐、表情切换、窗口拖动、面板遮盖、截图和诊断输出。
7. 形成绑定的渲染决策和 Phase 1 约束。

### 不包含

- Todo 数据模型、持久化、提醒或完成逻辑。
- 真实对话、LLM、Prompt、记忆或剧情检索接入。
- 托盘、设置页、开机启动、安装包或更新机制。
- 多显示器兼容补丁的最终实现。
- FGO 原生对话框或字体的提取与分发。
- 将 spike 直接演进为正式应用。

## 素材准入修正

### 已发现的问题

`raw/full_body.png` 已具有有效透明背景，但当前内容管线仍对它执行边缘背景移除。像素对比显示 runtime 相比 raw 改变了 23,211 个像素，其中 7,998 个原本可见像素被变成全透明。现有美术自动 QA 没有识别这种人物区域侵蚀。

因此，2026-08-26 的美术 readiness 不能继续作为 runtime 可直接用于渲染的充分证据。在修复、重新生成和视觉审核前，当前 runtime 素材不得用于 Phase 0 的渲染器选型。

### 修复原则

- 输入裁切已经具有有效 Alpha 时，不再执行颜色容差背景移除。
- 处理结果不得降低原始人物区域 Alpha；必要的格式规范化必须保持 RGBA 像素不变。
- 自动测试必须覆盖：已有透明背景保持、半透明抗锯齿保持、深色服装保持、人物区域 Alpha 不降低。
- 修复后重新生成 manifest 哈希、自动 QA 和视觉联络表。
- Phase 0 正式矩阵只使用重新通过准入的素材；修复期间可使用 raw 做探针开发，但不能据此签署最终决策。

## 角色合成模型

### 图层语义

运行时角色由两个图层组成：

1. `full_body`：稳定的全身身体底图。
2. `r01c01`–`r07c04`：覆盖全身图顶部区域的完整上半身表情差分层。

切换表情时只替换表情层。身体底图、窗口尺寸、人物底部锚点和面板附着点保持不变。表情 PNG 不是互斥的整个人物贴图，也不是只包含脸部的小型贴片。

### 合成几何

源身体画布为 303×603 px，表情画布为 256×240 px。Phase 0 必须校准表情层相对身体画布的偏移，不允许渲染器根据 ID 写特殊分支。

初始候选偏移为水平居中的约 `(24, 0)`，但最终参数必须通过像素重合与视觉检查确认。校准重点是头发轮廓、衣领、肩部和上衣接缝。

正式 manifest 需要表达以下 `composition` 信息：

- 身体底图稳定 ID；
- 默认表情稳定 ID；
- 每个表情层的相对路径；
- overlay 的源像素偏移；
- overlay 的覆盖尺寸或裁剪范围；
- 身体底部中心锚点；
- 面板附着参考点；
- 默认统一显示比例 0.60。

其他服装可以声明不同的合成参数，运行时不得假设所有素材都使用玛修常服的尺寸和偏移。

## 统一缩放与 DPI

身体层、表情层、overlay 偏移、人物锚点和面板附着点必须共享同一个源画布变换。

逻辑显示尺寸按源画布百分比计算：

- 50%：约 152×302 DIP；
- 60%：约 182×362 DIP，默认值；
- 75%：约 227×452 DIP。

得到逻辑坐标后，再根据当前 Windows DPI 转换为物理像素。画像边界和锚点最终对齐到整数物理像素，避免身体层与表情层分别取整造成接缝。

收到 `WM_DPICHANGED` 后，探针在布局稳定时重新计算整套合成变换、面板位置和诊断信息。不得只调整窗口而保留旧的图层物理坐标。

## 探针架构

探针为独立 `.NET 8 WPF` solution，位于 `spikes/rendering`，不依赖 Python 内容管线、LLM 或 Codex 插件。

### ArtBundleLoader

- 通过 `--bundle <manifest.json>` 加载经过准入的素材包。
- 校验文件存在、哈希、Alpha、稳定 ID、composition 参数和默认表情。
- 输出身体底图、表情集合与统一合成参数。
- 允许开发期显式选择 raw，但最终验收必须使用重新通过准入的 bundle。

### CompositePortrait

- 持有身体底图和当前表情层。
- 在源像素坐标中应用 overlay 偏移。
- 对整个组合应用一次统一缩放和 DPI 对齐。
- 表情切换不改变外部逻辑尺寸或人物底部锚点。

### IRenderSurface

两个后端实现同一契约：加载 bundle、选择表情、设置统一比例、捕获最终组合画面并释放资源。

- WPF 后端使用同一固定画布中的两层 `Image`。
- Skia 后端在同一 surface 上依次绘制身体与表情。
- 两个后端必须使用相同素材、偏移、缩放、采样目标和截图范围。

### ProbeWindow

- 创建透明、无边框、可拖动的验证窗口。
- 透明模式在 HWND 创建前通过启动参数选择，进程内不切换。
- 承载人物、原创覆盖面板和可隐藏诊断浮层。
- 处理 DPI 变化、渲染器切换、表情切换、压力循环和截图。

### ProbeRecorder

输出 JSON Lines 样本、PNG 截图和会话摘要。记录至少包含：

- 时间、Windows 版本和会话 ID；
- 渲染器与透明模式；
- 表情 ID、统一缩放比例和面板状态；
- Windows DPI、逻辑尺寸和物理尺寸；
- overlay 偏移与最终锚点；
- 表情切换耗时与进程工作集；
- 截图路径与人工备注。

诊断不得包含聊天内容、Prompt、API Key 或其他用户隐私数据。

## 原创覆盖面板

Phase 0 使用原创的“迦勒底终端感”覆盖面板，不复制 FGO 原生对话框素材。

视觉基线：

- 深蓝半透明主体；
- 切角轮廓；
- 少量青色和洋红状态线，呼应玛修配色；
- 字体采用 `Segoe UI`，中文回退 `Microsoft YaHei UI`；
- 面板覆盖人物腰部以下，不永久裁掉身体素材；
- 面板关闭后显示完整人物。

探针提供“对话”和“Todo”两种静态状态，只验证层级、文字清晰度、遮盖范围、透明边缘与拖动稳定性，不实现业务功能。

## 探针交互

- `F1`：WPF 渲染器；
- `F2`：SkiaSharp 渲染器；
- `←/→`：切换 28 个表情；
- `1/2/3`：切换 50% / 60% / 75%；
- `P`：显示或隐藏覆盖面板；
- `T`：切换对话/Todo 静态状态；
- `C`：等待渲染完成后截图并记录样本；
- `R`：运行 28 个表情 × 10 轮压力切换；
- `Esc`：退出。

## 分阶段验证

### 1. 素材与合成准入

- 重新生成的 runtime 通过 Alpha 保留测试和视觉审核。
- 28 个表情全部加载成功。
- 每个表情与身体底图的头发、衣领、肩部和上衣接缝无可见双边或错位。
- 表情切换不改变身体底部位置、窗口逻辑尺寸或面板附着点。

任何硬失败均阻止进入渲染器比较，不允许静默使用默认表情掩盖素材错误。

### 2. 渲染器选择

先固定常规 WPF 透明窗口，在 Windows 100%、125%、150% DPI 下比较 WPF 与 SkiaSharp。主要档位为 60%，精细样本为：

- `r01c01` 微笑交谈；
- `r02c02` 轻微惊讶；
- `r04c04` 羞涩微笑；
- `r07c03` 开怀欢笑。

其余表情参与全量切换与压力测试。

当 WPF 在所有已观察场景中没有明显画质或稳定性劣势时选择 WPF。只有 SkiaSharp 在至少两个缩放/显示场景中肉眼明显更清晰，且压力测试后工作集不超过 WPF 约 30%、无额外跨 DPI 回归时，才选择 SkiaSharp。

### 3. 透明窗口模式选择

使用胜出的画像渲染器比较：

- 常规 WPF：`AllowsTransparency=True`；
- DWM 模式：`AllowsTransparency=False`，使用受控的窗口样式和 DWM 组合。

常规 WPF 为默认选择。DWM 必须保持逐像素透明、无黑边、拖动和点击行为稳定，并在空闲 CPU/GPU、内存或交互流畅度上呈现明确收益，才可胜出。轻微内存差异不足以抵消 Win32 样式钩子的复杂性。

### 4. 最终组合验证

胜出的组合覆盖：

- 50%、60%、75% 角色比例；
- Windows 100%、125%、150% DPI；
- 面板关闭、对话状态和 Todo 状态；
- 28 个表情 × 10 轮压力切换；
- 窗口拖动、面板切换和截图。

混合 DPI 显示器移动记录为 `not observed`，不得根据单显示器缩放推断其结果。

## 性能与稳定性口径

- 以趋势和后端相对差异为主，不设置脱离机器环境的绝对内存门槛。
- 压力切换后执行受控回收，工作集不得持续单调增长。
- 表情切换应无肉眼可见停顿或白闪；目标是在一个显示帧内完成可见更新。
- 空闲 CPU/GPU 和工作集记录多次样本；单次瞬时值不直接判失败。
- 若 SkiaSharp 工作集高出 WPF 超过约 30%，除非画质收益显著且无法由 WPF 设置消除，否则不选择 SkiaSharp。

## 错误处理

- manifest、文件、哈希、Alpha 或 composition 参数无效时，启动失败并显示明确错误。
- 表情切换失败时保留上一个有效表情并记录错误，但该会话不能签署 PASS。
- 截图或诊断写入失败时在 UI 中提示，不影响原始素材。
- 所有外部 FGO 素材只读；生成物写入被 Git 忽略的 `spikes/rendering/artifacts`。
- 不修改 `D:\fgo_unpack\fgo_assets` 中的来源文件。

## 自动测试

自动测试至少覆盖：

- 已有 Alpha 的素材不被二次侵蚀；
- bundle manifest 与 composition 模型校验；
- overlay 坐标和统一百分比缩放；
- 100%、125%、150% DPI 的整数物理像素对齐；
- WPF 与 Skia 输出尺寸、Alpha 和合成层级一致；
- 表情切换不改变身体底部锚点；
- JSON Lines 结构稳定且不包含敏感字段；
- 无效启动参数和缺失资源明确失败。

真实桌面合成、透明边缘、拖动闪烁与 Windows DPI 行为仍需要人工矩阵，不能由离屏测试替代。

## 交付物与验收

Phase 0 交付：

1. 修复并重新准入的玛修常服 runtime bundle。
2. 独立 WPF 渲染探针及自动测试。
3. 被忽略的本地截图和 JSONL 证据。
4. `docs/decisions/0001-windows-portrait-renderer.md`，记录绑定选择。
5. 更新后的 Phase 1 资源与渲染约束。

Phase 0 通过条件：

- 重新准入的真实素材在目标 DPI 和比例下无明显透明边缘异常；
- 28 个表情与身体层合成稳定，无可见接缝和位置跳动；
- 窗口拖动、表情切换和覆盖面板稳定；
- 压力切换没有持续资源增长；
- WPF/SkiaSharp 与 conventional/DWM 均有基于预定规则的明确选择，或有证据拒绝 WPF 技术路线；
- 决策文档明确记录未观察的混合 DPI 风险，不把它伪装成已通过。

## 后续关系

Phase 1 根据本规格和最终决策文档重新实现正式桌宠。它必须保留经过验证的 bundle contract、overlay 合成、统一缩放、DPI 对齐和资源释放规则，但不得直接复制未经生产化评审的 spike 窗口与诊断代码。
