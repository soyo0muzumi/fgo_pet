# FGO Pet Phase 5.3：Agent 配置引导设计

日期：2026-09-02

状态：待审阅

前置：Phase 5.1/5.2 已在本地 `main` 合入；本设计只处理已安装组件的应用内配置，不扩展安装器能力。

## 1. 决策

Phase 5.3 采用一个最小的“设置 → AI 模型与连接 → Agent”配置闭环：

1. 应用展示 Relay、Adapter 和配对来源的当前状态；
2. 用户可以批准或拒绝待配对来源；
3. 用户从 Adapter 已登记的目标中按项目名称选择 allowlist；
4. 用户可以保存来源开关和项目授权、测试连接、撤销来源并重新配对；
5. 用户可以复制脱敏诊断摘要；
6. 不在本切片中安装、修复、卸载 Relay/Adapter 或 Codex 插件。

目标名称是唯一的用户可见项目标识。UI 不要求用户复制或输入不透明 `TargetId`，也不展示本地绝对路径。`TargetId` 只作为内部授权键保存和传输。

## 2. 背景与当前基线

当前设置页已经具备以下基础：

- Relay/Adapter 连接测试和运行状态快照；
- 待批准来源的批准/拒绝；
- 已批准来源的启用开关、来源信息、allowlist 保存和撤销；
- Phase 5.1 的容量状态与安全归档入口；
- Adapter 侧 `CodexTargetCatalog` 和 `target list`，目标包含稳定 ID、项目名称、目录和只读属性。

当前缺口是 allowlist 仍要求用户编辑换行分隔的 ID，安装引导文字仍把用户导向 CLI，且没有重新配对、诊断复制和目标名称列表的应用内路径。

## 3. 范围

### 3.1 本切片包含

- 已安装 Adapter 的目标目录读取；
- 目标以项目名称呈现的多选列表；
- 已有 allowlist 与目标名称之间的安全映射；
- 来源批准、来源启用、allowlist 保存、连接测试、撤销和重新配对入口的统一文案与状态反馈；
- 不含秘密、Prompt、对话正文和绝对路径的诊断摘要复制；
- Relay/Adapter 不可用时的离线设置降级。

### 3.2 本切片不包含

- 下载、安装、升级、修复、卸载 Relay/Adapter；
- 自动安装 Codex 插件、修改 PATH 或写入用户项目配置；
- “允许全部项目”快捷方式；
- 新的顶级导航或独立 Agent 管理应用；
- 将目标目录写入 App 设置、Relay 状态、业务备份或诊断日志；
- 第二个 Agent 平台。

## 4. 用户流程

### 4.1 首次配置

1. 用户打开 Agent 设置页。
2. App 展示 Relay/Adapter 是否已安装、是否运行，以及当前协议状态。
3. Adapter 已运行但来源未批准时，App 展示来源名称、实例和能力，用户选择批准或拒绝。
4. 批准后刷新来源状态和 Adapter 目标列表。
5. 用户看到项目名称列表，勾选需要允许的项目。
6. 用户明确开启来源并保存。
7. App 展示保存结果，并允许执行连接测试。

未安装组件时，当前切片只说明“组件未安装，暂不能配置”，并保留离线功能；不调用安装器。

### 4.2 修改授权

用户只操作项目名称和来源开关。保存时 App 将当前勾选项映射回目标 ID，并调用现有 Relay 权限更新边界。任何未解析的既有 ID 默认保留，避免目标列表短暂不可用时意外清空授权。

### 4.3 撤销与重新配对

- 撤销必须经过现有确认流程；Relay 确认撤销后，App 才将相关活动执行标为本地取消。
- 重新配对是撤销后的新注册流程：App 清楚说明旧授权失效，触发 Adapter 现有身份恢复/重新注册路径；不要求用户编辑凭据或复制请求 ID。
- 重新配对不会清除 Todo、对话、记忆、执行历史或其他业务数据。

### 4.4 诊断复制

诊断摘要只包含：协议版本、Relay/Adapter 状态、来源类型、来源实例的脱敏短标识、连接状态、目标数量、授权数量、只读目标数量、最近一次安全错误码和观察时间。

诊断摘要不得包含：凭据、请求 nonce、Prompt、对话正文、任务正文、目标 ID 原文、本地绝对路径、用户名、环境变量、命令行参数或日志原文。复制失败不影响设置状态。

## 5. 领域模型与数据边界

Adapter 继续拥有目标目录的权威状态：

```text
Adapter target catalog
  TargetId       opaque stable authorization key
  DisplayName    user-visible project name
  Directory      Adapter-only execution data
  ReadOnly       user-visible capability flag
```

App 侧只建立短生命周期的展示模型：

```text
AgentTargetOption
  TargetId       internal, never rendered or copied
  DisplayName    rendered project name
  IsReadOnly     rendered as a capability badge
  IsSelected     local editor state
  IsResolved     whether current catalog contains the persisted ID
```

`Directory` 可以在 Adapter 的本地查询结果中短暂存在，但不得进入 App 持久化模型、Relay message、业务数据库、备份清单、诊断摘要或普通日志。UI 的绑定和复制逻辑不接受目录字段。

现有 `AllowedTargetIds` 仍是唯一的权限事实来源。项目名称只是可视化投影；名称变化不改变授权，目标 ID 变化也不会被名称相似性自动迁移。

## 6. 目标目录读取方案

### 6.1 方案比较

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 通过 Relay 新增目标目录协议 | 状态集中、调用形式统一 | 要扩展 App→Relay→Adapter 控制流，并处理路径边界 | 不用于 5.3 |
| App 直接读取 Adapter 目录文件 | 实现简单 | 重复 Adapter 校验逻辑，容易绕过目录所有权 | 不采用 |
| App 调用 Adapter 现有 `target list` | 复用 Adapter 校验和版本边界，不让路径进入 Relay | 需要本机受控进程调用与超时处理 | 5.3 推荐 |

### 6.2 推荐实现

新增 App/Infrastructure 的只读 `IAgentTargetCatalog` 查询服务，由它定位随应用发布的 Adapter companion executable，使用固定的 `target list` 参数执行一次短时查询：

- 不经过 shell，不接受用户拼接参数；
- 限制启动超时、总输出大小和目标数量；
- 只接受符合 Adapter 目标合同的 JSON；
- stderr 只映射为安全错误码，不原样展示；
- 查询失败返回明确的“Adapter 未安装/离线/目录不可用/响应无效”状态；
- 查询结果只在当前设置刷新周期内存在。

该方式仍然把 Adapter 作为目录权威来源，同时保持“文件系统路径不经过 Relay”的现有边界。后续如果需要实时双向管理，可在 Phase 5.4/5.5 单独设计本机管理协议，不提前把它带入本切片。

## 7. 设置页交互设计

### 7.1 来源卡片

每个已批准来源卡片包含：

- 来源显示名、类型、实例脱敏标识和 Adapter 版本；
- 在线/离线、已启用/已停用、是否有未保存修改；
- “刷新目标”“保存权限”“测试连接”“撤销来源”“重新配对”操作；
- 项目名称多选列表；只读目标显示只读标记，不改变授权语义。

移除原始的多行 ID 编辑框。对于历史配置中存在但当前目录未返回的 ID，显示为“已保存授权，当前目标不可用”，不显示 ID 原文；保存时保留它们，用户通过明确的移除操作才能删除。

### 7.2 空状态与错误

- 没有目标：说明需先使用受控目标登记流程，当前切片不提供登记按钮；
- Adapter 未安装：显示不可配置状态，不影响离线设置和其他功能；
- Adapter 运行但查询失败：显示重试入口和安全错误码；
- Relay 离线：目标名称仍可在本地查询时展示，但保存、撤销和测试按钮禁用并说明原因；
- 现有授权无法解析：保留授权，禁止“空列表保存即清空”。

### 7.3 安装引导文字

替换当前把用户导向 `target add`、手工 ID 和插件指南的说明，改为：

> Agent 仅会访问你明确选择的项目。请先批准来源，再从已登记的项目名称中选择并保存；未选择项目时不会派发任务。组件安装和插件注册将在后续安装流程提供。

## 8. 重新配对状态机

沿用现有 Adapter 身份存储和撤销恢复语义：

```text
已批准/已连接
      │ 撤销确认并收到 Relay ACK
      ▼
已撤销/需重新配对
      │ Adapter 清理旧 credential，生成新 nonce
      ▼
等待批准
      │ 用户批准
      ▼
已批准/可认证
      │ 连接测试成功
      ▼
已连接
```

任一阶段失败都保留可解释状态，不自动重试产生新的注册身份，不触碰业务数据。重复点击重新配对必须幂等，不得创建多个有效来源授权。

## 9. 协议与兼容性

本切片不改变现有 Relay 权限消息的字段含义：`update_permissions` 仍只接收来源身份、布尔启用状态和目标 ID 列表。目标目录查询使用 Adapter 的本机 CLI 合同，因此不新增 Relay message type，也不让目录字段进入 `AgentProtocolValidator`。

需要增加的共享边界仅限：

- App/Infrastructure 的目标查询结果合同和安全错误码；
- App ViewModel 的名称到 ID 映射；
- 既有设置页操作的重新配对/诊断命令入口。

查询服务不可用时，旧的 `AllowedTargetIds` 仍可被读取并保留；升级不会把旧授权强制转换为空列表。未来目标目录合同不兼容时显示版本不匹配，要求用户升级 Adapter，不尝试猜测字段。

## 10. 测试与验收

### 10.1 单元测试

- Adapter `target list` 的 JSON 解析接受合法名称、只读标记和稳定 ID；
- 拒绝超限输出、缺字段、重复 ID、路径型 ID、控制字符名称和错误合同；
- 查询超时、进程退出、非零退出码和 stderr 不泄露原文；
- 已保存 ID 能映射到名称；目录暂时缺失时既有 ID 保留；
- 名称变化不改变 ID 授权；名称相似不触发自动授权迁移；
- 诊断摘要不含凭据、路径、Prompt、正文和目标 ID；
- 重新配对的重复操作保持幂等。

### 10.2 设置页测试

- 页面显示项目名称而不是原始 ID 输入框；
- 勾选项目后保存发送正确的 ID 列表；
- 未解析授权不会因刷新或空列表保存而丢失；
- Adapter 缺失、Relay 离线和查询失败均保持离线设置可用；
- 测试连接、撤销、重新配对和复制诊断都有忙碌态、失败态和成功反馈；
- 不显示绝对路径，不把路径写入剪贴板诊断内容。

### 10.3 验收标准

- 普通用户无需编辑 JSON、复制目标 ID 或运行命令，即可批准来源、按项目名称选择授权并保存；
- 默认拒绝保持有效：未批准、未启用、未选择或已撤销来源均不能派发；
- Relay/Adapter 不可用时，桌宠、专注、对话、记忆和 Todo 等离线功能不受影响；
- 连接测试、撤销和重新配对不重复创建 Agent 任务，不清除业务数据；
- 合入前 Release build、相关 .NET 测试和路径/凭据隐私检查全部通过。
