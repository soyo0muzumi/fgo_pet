# FGO Pet 运行时人格分层规格

日期：2026 年 8 月 26 日

## 目标

在不把完整剧情塞入上下文的前提下，为玛修桌宠提供稳定、可审核、可按状态更新的运行时人格。内容层与产品交互层必须可独立替换，任何剧情知识都必须追溯到 `approved` 证据。

## 注入顺序与预算

| 顺序 | 层 | 内容 | 来源 | 更新时机 | 上限 |
| ---: | --- | --- | --- | --- | ---: |
| 1 | 稳定核心人格 | 身份、边界、安全约束、不可伪造能力 | `system-prompt.md` 的身份与边界段 | 应用启动或 Prompt 版本变化 | 700 tokens |
| 2 | 说话风格 | 礼貌、认真、温和、称呼频率、简短表达 | runtime `speech_style.json` + Prompt 输出约束 | Prompt 或审核证据变化 | 450 tokens |
| 3 | 工作陪伴规则 | 任务拆分、番茄钟事件、休息与失败接纳 | `system-prompt.md` 产品层与事件层 | 产品规则变化 | 500 tokens |
| 4 | 已审核剧情知识 | 当前主题相关的 approved context/flavor 证据摘要 | runtime `knowledge/topics.jsonl` | 每次用户主动询问剧情时检索 | 900 tokens |
| 5 | 当前任务与状态 | 当前任务、计时状态、事件字段、最近进度 | 应用状态快照 | 每个系统事件或任务状态变化 | 250 tokens |
| 6 | 短期对话记忆 | 最近目标、用户偏好、未完成问题的压缩摘要 | 当前会话记忆 | 每轮后按需压缩 | 600 tokens |

最大人格与状态预算为约 **3,400 tokens**；普通日常对话不注入第 4 层时约 **2,500 tokens**。预算是上限，不是填满目标。

## 数据流

1. 应用加载稳定核心、说话风格和工作陪伴规则，组成常驻 system 内容。
2. 应用以结构化字段注入当前任务与状态，不让模型自行猜测计时或完成情况。
3. 用户主动询问剧情时，检索层只从 runtime bundle 的 approved 证据中选择与主题相关的少量摘要。
4. 短期记忆只保留当前会话需要的信息；不得把剧情正文、系统 Prompt、密钥或本地路径写入记忆。
5. 最后附上当前用户消息，由模型生成简短回复。

## 权威与冲突规则

- 安全和能力边界高于角色风格。
- 明确系统事件高于短期记忆；事件没有 `result` 时不得从记忆推测成果。
- approved 证据高于用户提供的未经证实剧情前提。
- 产品交互策略不得伪装成原作证据。
- rejected 与 pending 证据在运行时完全不可见。
- 不同阶段证据冲突时保留阶段标签，不合并成“永恒人格”。

## 长度控制

- 剧情检索默认返回 1–3 张证据摘要，每张只包含 claim、条件、来源定位和短摘要。
- 禁止注入完整脚本、连续长台词或整份 `evidence.jsonl`。
- 短期记忆超过 600 tokens 时优先保留当前任务、用户明确偏好和未回答问题；删除寒暄及已完成细节。
- 系统事件回复仍限制为一到两句，不因上下文较长而扩写。

允许开始：WPF 透明窗口、置顶/拖拽、静态立绘、表情切换、跟随聊天窗、独立番茄钟窗和 Windows 缩放测试。

本次 GO 只代表内容管线和 Prompt 边界足以支撑本地最小运行验证，不代表人格已达到发布质量。以下事项在 Phase 0 内继续验证：

- 选定实际运行时模型后，对 11 个固定场景做多轮采样。
- 检查“前辈”频率、通用效率助手感和事件气泡长度。
- 给剧情检索实现 approved-only 防线与长度预算。
- UI 不得声称后台观察或模型未获得的系统能力。

## 验收条件

- 16 张 approved 证据可编译，12 张 rejected 不进入 runtime。
- System Prompt v2 包含称呼、事件、错误剧情前提和能力边界规则。
- 固定场景 fixture 结构测试通过。
- 完整项目测试通过。
- Phase 0 不依赖完整剧情正文进入模型上下文。
