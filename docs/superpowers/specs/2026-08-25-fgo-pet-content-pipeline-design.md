# FGO Pet 美术与剧情内容管线设计规格

日期：2026-08-25

状态：已批准

首个目标从者：玛修·基列莱特（Servant ID `800100`）

## 1. 目的与实施顺序

本规格定义 FGO Pet 在进入桌宠渲染验证前需要完成的内容准备工作。Phase 0 不使用随意挑选的测试图或临时人物简介，而使用经过整理、可追溯的玛修首版内容包。

实施顺序调整为：

1. 建立美术资源索引与整理流程。
2. 获取并标准化剧情正文。
3. 从剧情生成可审核的人设证据卡与人格摘要。
4. 产出玛修首个内容包。
5. 使用真实立绘、表情和锚点进入 Phase 0 渲染验证。

首轮只交付玛修内容，但数据模型、命令和目录结构不得写死玛修特例。

## 2. 范围与边界

### 2.1 本阶段包含

- 扫描 `fgo_assets/servant/800100` 中已有美术资源。
- 区分灵基、服装、剧情立绘、表情差分、礼装和非运行时素材。
- 建立外观、表情、图像资源和剧情角色形象之间的映射。
- 获取 CN/JP 剧情目录、脚本元数据和一批玛修相关正文。
- 将 FGO 演出脚本解析为可追溯的结构化场景与台词。
- 从有效场景生成结构化人设证据卡。
- 将证据卡编译为常驻人格摘要、按需剧情知识和语言风格资料。
- 生成人工审核报告、异常报告和首版玛修内容包。

### 2.2 本阶段不包含

- WPF 桌宠窗口、聊天 UI、番茄钟或 Codex 插件实现。
- 自动下载和发布全部 FGO 剧情正文。
- 将完整剧情原文提交到 GitHub 或随应用发布。
- 未经审核地把 LLM 生成内容认定为官方设定。
- 自动为所有服装补画缺失表情。
- 语音下载、语音识别、语音合成和声纹处理。
- 一次性处理所有从者。

## 3. 数据来源与权威顺序

### 3.1 来源优先级

剧情文本采用以下权威顺序：

1. 国服官方中文文本。
2. 对应的日服官方文本。
3. 明确标记为非官方翻译的中文事实摘要。

日服文本用于补足国服尚未发布、国服数据缺失或需要核对语义的内容。机器翻译只能帮助人工理解和生成候选证据，不能标记为国服官方文本，也不能覆盖可用的官方中文。

美术资源以本地 Atlas Academy 资源提取结果为底稿。任何优化、裁切、缩放或格式转换都生成派生副本，不修改原始文件。

### 3.2 已验证的数据结构

Atlas Academy 提供剧情搜索和原始脚本地址。探针脚本 `0200040010` 验证了 CN 正文可被获取，并包含稳定的演出标记：

- `charaSet`：槽位、形象资源 ID 和显示名。
- `charaTalk`：当前发言槽位。
- `charaFace`：当前表情差分编号。
- `＠角色名`：台词署名。
- `[r]`：台词内换行。
- `[k]`：台词结束。
- `scene`、`bgm`、`se`：背景、音乐和音效。
- 选择、分支、跳转以及角色移动等其他演出命令。

本地 `mstQuestScript` 是章节目录和关联元数据，不含正文。正文必须从剧情脚本资源层获取。

### 3.3 来源关联

脚本可能属于不同容器，来源解析不得只检查 Quest：

- `mstWar`：章节或地图级开场脚本。
- Quest 及 Quest Phase：主线小节和战斗前后剧情。
- Event：活动、周年、情人节和特殊剧情。
- Interlude：幕间物语。
- 其他材料或特殊脚本容器。

每个脚本至少保留地区、脚本 ID、容器类型、容器 ID、章节顺序、源地址、抓取时间、内容哈希和数据版本。无法关联容器的脚本进入异常报告，不因关联失败而丢弃正文。

## 4. 公开仓库与本地数据边界

公开 GitHub 仓库可以包含：

- 抓取器、解析器、结构定义和测试夹具。
- 不含连续剧情正文的索引摘要。
- 抽象后的人设证据卡和人格规则。
- 内容包清单、资源引用和校验信息。
- 人工审核模板与异常报告模板。

公开仓库不得包含：

- 完整 CN/JP 剧情正文缓存。
- 可恢复为完整章节的大段连续台词。
- 未经授权重新分发的全量原始美术资源。
- API Key、用户路径或本地环境信息。

原始剧情默认存放在仓库外的 `fgo_assets/story_cache`。公开内容中的证据只保留来源定位、事实摘要和必要的极短校对片段。生成报告默认不复制大段原文。

## 5. 总体架构

内容管线分为六个彼此独立的步骤：

1. `catalog`：建立剧情目录、来源索引和美术资源索引。
2. `fetch`：增量抓取所需正文并验证哈希。
3. `parse`：将原始演出脚本转为无损的规范化剧情文档。
4. `curate`：筛选玛修相关场景，建立美术映射和人工标注。
5. `extract`：用规则与 LLM 生成候选人设证据卡。
6. `compile`：审核、合并并产出运行时内容包和 Prompt 资料。

每一步只依赖上一步的稳定输出，支持单独重跑。LLM 生成失败不得破坏已抓取或已解析的数据；更换模型不需要重新下载正文。

## 6. 剧情抓取设计

### 6.1 首轮抓取范围

首轮采用“完整目录、玛修相关正文”的范围：

- 获取 CN/JP 的剧情目录、容器关联和角色映射。
- 使用官方中文名、日文名、角色资源 ID 和已知形象 ID 搜索玛修候选脚本。
- 下载候选脚本正文，而不是首轮下载全部剧情正文。
- 对候选脚本做本地解析后再确认是否真正包含玛修。
- 其他剧情只保留目录与来源 ID，未来按需增量获取。

只按“玛修”字符串检索会遗漏化名、未知署名和只通过立绘资源出现的场景，因此候选发现同时使用：

- 中文和日文显示名及常见写法。
- `charaSet` 中的玛修形象资源 ID。
- 剧情角色形象到 Servant `800100` 的映射。
- 容器元数据中的关联角色或从者。
- 人工补充的脚本 ID 白名单。

### 6.2 缓存与增量更新

每次抓取记录 HTTP 状态、来源 URL、抓取时间、字节数、内容哈希和上游数据版本。

- 相同哈希不重复解析。
- 支持断点重试和单脚本重抓。
- 404、超时、限流和格式异常分别记录。
- CN 缺失时尝试 JP，但保留 `translation_status`。
- 上游正文发生变化时保留旧哈希及差异状态，避免无声覆盖已审核证据。
- 抓取过程不得将正文写入 Git 跟踪目录。

## 7. 原始脚本解析

### 7.1 状态机解析器

FGO 演出命令会持续影响后续台词，因此解析器必须维护状态，不能将每一行当成独立记录。状态至少包括：

- 当前场景和背景。
- 角色槽位到显示名、形象 ID 的映射。
- 当前发言槽位。
- 每个槽位当前表情 ID。
- 当前音乐、音效和必要的演出上下文。
- 当前分支、选择和标签路径。

遇到未知命令时，解析器保留原始命令和行号，继续处理后续文本，并将未知类型计入兼容性报告。未知演出命令不能导致整篇脚本被丢弃。

### 7.2 规范化剧情文档

第一层输出追求可追溯和尽量无损，不做人设结论：

```json
{
  "schema_version": 1,
  "source": {
    "region": "CN",
    "script_id": "0200040010",
    "container_type": "war_opening",
    "container_id": 204,
    "content_hash": "sha256:..."
  },
  "cast": {
    "B": {
      "display_name": "玛修",
      "figure_id": "98001000",
      "servant_id": 800100
    }
  },
  "scenes": [
    {
      "scene_index": 1,
      "background_id": "60300",
      "utterances": [
        {
          "order": 2,
          "speaker": "玛修",
          "actor_slot": "B",
          "figure_id": "98001000",
          "face_id": 13,
          "text": "规范化后的台词文本",
          "branch_path": [],
          "raw_range": {"start_line": 48, "end_line": 51}
        }
      ]
    }
  ],
  "unknown_commands": []
}
```

文本规范化处理换行、注音、名字占位符和显示控制标记，但同时保留原始行号或字节区间，以便回查。

### 7.3 CN/JP 对齐

CN/JP 优先通过相同脚本 ID、容器和台词顺序对齐。无法直接对齐时使用角色序列、场景边界和文本相似结构辅助匹配。

每条对齐记录标记：

- `official_cn`：存在国服官方文本。
- `jp_fallback`：仅有日服文本。
- `alignment_uncertain`：可能错位，需要人工确认。
- `cn_jp_divergence`：语义或内容差异明显。

运行时人格优先使用 CN 事实表述；JP 原文仅作为补充证据或校对来源。

## 8. 剧情筛选与价值分级

剧情类型不是最终权威等级。活动、幕间和特殊章节可能包含重要主线信息，不能因为属于活动就自动降级。

筛选分为三步：

1. 直接相关性：玛修发言、登场、被重点讨论或事件明确影响玛修。
2. 人设价值：是否体现性格、价值观、关系、成长、稳定语言习惯或关键经历。
3. 权威修正：主线关联度、时间线位置、是否为平行/搞笑语境、是否与其他设定冲突。

场景分级：

| 等级 | 定义 | 使用方式 |
|---|---|---|
| Core | 稳定人格、核心关系和关键成长 | 编译进常驻人格 Prompt |
| Context | 特定经历、关系细节和条件性表现 | 按主题检索 |
| Style | 有代表性的措辞、礼貌程度和表达习惯 | 编译语言风格规则 |
| Flavor | 节日、搞笑或特殊活动表现 | 低权重日常彩蛋 |
| Archive | 无明显人设价值或大量重复内容 | 只存本地索引 |

系统应保留人工提级、降级、排除和重新归类能力，并记录修改原因。

## 9. 人设证据提取

### 9.1 两阶段提取

规则层先完成确定性工作：

- 切分场景和连续对话窗口。
- 标记玛修发言、相关人物和当前表情。
- 排除明显的战斗系统说明和纯演出噪声。
- 聚合同一话题的相邻台词。

LLM 层只根据提供的场景窗口生成候选证据，不允许使用未提供的外部知识。每个结论必须引用来源脚本和场景位置；不能找到依据的结论应被拒绝。

### 9.2 证据卡结构

```json
{
  "schema_version": 1,
  "subject": "mash",
  "category": "relationship",
  "claim": "抽象后的事实或行为倾向",
  "conditions": ["适用情境"],
  "behavior": ["可用于日常对话的行为规则"],
  "speech_traits": ["语言习惯"],
  "timeline": "适用剧情阶段",
  "authority": "context",
  "confidence": 0.9,
  "translation_status": "official_cn",
  "sources": [
    {
      "region": "CN",
      "script_id": "0200040010",
      "scene_index": 1,
      "utterance_orders": [2, 3]
    }
  ],
  "review": {
    "status": "pending",
    "notes": null
  }
}
```

### 9.3 合并与冲突

- 多个独立剧情重复支持的结论提高置信度。
- 同一脚本的重复台词不视为独立证据。
- 不同剧情阶段的差异保留时间条件，不强行合并。
- 特殊活动或平行语境与主线冲突时保留双方，并降低特殊语境权重。
- 对角色成长造成的真实变化，以时间线条件表达，而不是把早期与晚期人格混成一个平均值。
- LLM 不得自行把低权重 Flavor 结论提升为 Core。

## 10. Prompt 资料编译

运行时不注入整章剧情，也不直接读取原始脚本。内容包生成三种资料：

### 10.1 常驻人格层

由已审核的 Core 证据编译，目标约 1000 至 2000 中文字，包括：

- 核心性格与价值观。
- 与用户/御主的关系定位和默认称呼“前辈”。
- 日常陪伴方式和情绪支持边界。
- 稳定表达习惯。
- 明确需要避免的违和行为。
- 角色身份与桌面陪伴者身份的融合方式。

### 10.2 按需知识层

Context、Style 和 Flavor 证据按人物、关系、事件、地点、情绪和主题建立本地索引。聊天时只检索少量与当前问题相关的卡片。

### 10.3 当前状态层

运行时由应用提供，不写入静态内容包：

- 当前灵基和服装。
- 当前表情与番茄钟状态。
- 重要任务进度事件。
- 用户允许保存的相关长期记忆。

最终请求由“常驻人格 + 当前互动规则 + 相关证据卡 + 当前状态 + 输出格式约束”组成。

## 11. 美术资源整理

### 11.1 已知输入

`fgo_assets/servant/800100` 当前包含 `nice.json` 和约 127 张 PNG，混合了多种灵基、服装、剧情形象和表情差分。现有文件不能按文件名直接视为桌宠表情集合。

### 11.2 索引字段

每张图记录：

- 原始路径和内容哈希。
- 像素尺寸、Alpha 边界和透明像素比例。
- Atlas 资源类别及资源 ID。
- Servant、形象、灵基、服装和剧情形态候选关联。
- 是否为完整立绘、头像、窄图、礼装或非目标素材。
- 人工确认状态。

### 11.3 外观与表情映射

每套可用外观独立配置：

- 默认立绘。
- 十类桌宠语义表情：默认、微笑、担心、惊讶、生气、疲惫、认真、害羞、庆祝、安慰。
- 原始 `face_id` 到图片资源的映射。
- 缺失表情回退链。
- 统一画布、脚底锚点、气泡锚点、裁切和缩放。

FGO 的 `face_id` 是特定角色形象下的差分编号，不是跨角色通用情绪。语义映射必须由资源预览和剧情语境共同确认，不可用数字硬编码。

### 11.4 半自动审核

工具生成缩略图总览、同组叠加对比和剧情使用频次，人工完成：

- 灵基/服装归类确认。
- 表情语义命名。
- 锚点和裁切调整。
- 剧情专用或不适合作桌宠素材的排除。

处理输出写入整理工作区；原始素材保持只读。

## 12. 内容包输出

玛修首版内容包建议结构：

```text
mash/
├─ manifest.json
├─ portraits/
│  └─ <costume-id>/
├─ craft_essences/
├─ dialogue/
│  └─ local_lines.json
├─ persona/
│  ├─ core_persona.json
│  ├─ speech_style.json
│  └─ evidence_cards.jsonl
└─ knowledge/
   ├─ topics.jsonl
   └─ source_index.json
```

`manifest.json` 声明内容包版本、Servant ID、外观、表情、锚点、回退规则、Prompt 资料版本和文件哈希。发布包中的来源索引不得包含完整原文。

## 13. 人工审核与报告

每次编译生成以下报告：

- Core 证据及其出处。
- CN 缺失、JP 回退和非官方翻译项。
- CN/JP 明显差异。
- 主线、活动或不同时间阶段的设定冲突。
- 低置信度、疑似错认说话人和无法关联容器的场景。
- 重复、合并、降级和舍弃的证据。
- 未映射或低置信度的 `face_id`。
- 外观缺失表情及其回退结果。
- 未知脚本命令及出现次数。

人工审核只需聚焦高价值结论和异常项，不要求逐行通读全部原始剧情。

## 14. 错误处理与可重复性

- 网络错误按脚本粒度重试，不清空已有缓存。
- 解析失败保留原文、错误位置和解析器版本。
- 未知命令保留为原始事件并继续解析。
- LLM 输出必须通过 JSON Schema 和来源引用校验。
- 不合格的候选卡进入拒绝报告，不污染已审核资料。
- 每个派生文件记录输入哈希、工具版本和生成配置。
- 相同输入与配置应产生确定性的规范化剧情文档。
- 更换 LLM 后可以只重跑证据提取与编译阶段。

## 15. 测试策略

### 15.1 抓取

- CN 成功、CN 缺失后 JP 回退、404、超时和限流。
- 哈希未变化时跳过，变化时保留差异状态。
- 正文不会写入 Git 跟踪目录。

### 15.2 解析

- 角色槽位切换、表情持续状态、多角色同场和匿名署名。
- 台词换行、注音、占位符、选择和分支。
- War、Quest、Event 和 Interlude 来源关联。
- 未知命令不会导致已识别台词丢失。
- 使用一小段合法测试夹具验证可重复输出，不提交完整剧情。

### 15.3 证据提取

- 每个 claim 至少有一个有效来源。
- 无来源结论被拒绝。
- Flavor 不会自动提升为 Core。
- 同一脚本重复证据不会虚增置信度。
- 时间阶段冲突不会被无条件合并。

### 15.4 美术

- 文件存在性、哈希、尺寸和 Alpha。
- 表情回退链无循环且最终可解析。
- 同套外观切换表情时锚点偏移处于允许范围。
- 每套外观至少存在可用默认立绘。

## 16. 首版验收标准

进入 Phase 0 前必须满足：

- 能从 Atlas CN 搜索并抓取指定剧情脚本，CN 缺失时能标记并回退 JP。
- 至少一个真实剧情脚本被稳定转换为规范化剧情文档。
