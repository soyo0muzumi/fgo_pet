# Phase 5：先让现有功能适合长期使用

日期：2026-09-01。依据：Phase 4 收尾检查；本文件调整此前路线方向，不启动 Phase 5 实现。

状态更新：Phase 4 本轮主要 Windows 环境机器门禁、用户完成态/重启/撤销验收及只读数据库核对已通过。Phase 5 可按下述优先级推进；代码已通过 `59347f1` 快进合并到本地 main；合并后 Release 构建、.NET 697/697 和 Python 105/105 再次通过。尚未推送或发布。

## 决定

**Phase 5 优先把当前功能变成可长期使用、可恢复、可安装的产品；暂不以增加应用感知、收藏等新功能为主要目标。**

原因是当前风险集中在跨进程任务状态、人工配置成本、数据恢复和内容打包。继续增加事件来源会扩大这些风险，不能改善已有流程的可靠性。

进入 Phase 5 的前提：Phase 4 核心回归通过，完成态、重启和撤销经用户桌面验收确认。自动化测试与人工验收单独记录，不互相替代。

## 5.1 日常使用与数据安全

先交付三个小闭环，不重做布局和架构：

1. **任务可理解。** 完成任务进入历史；等待、失败、中断、离线、权限失效的状态和下一步动作明确；既有任务重试不重复执行。先收集 Phase 4 用户验收反馈，再选必须修改的界面文案和入口。
2. **配置成本降低。** 现有目标注册需要 CLI、复制不透明项目 ID；为本地目标注册、选择、配对状态提供一致的引导。权限仍默认拒绝，必须显式选择项目；不能以默认允许所有项目来降低门槛。现有设置入口够用，不增加新顶级导航。
3. **备份可以恢复。** 建立版本化私有备份、导入前检查、一致性数据库快照、失败回滚及干净目录 round-trip。可分享的脱敏导出保持独立，不把它伪装为完整备份。

其中应优先补“派发结果未知”的用户核对入口。Phase 4 保留安全的执行预留，网络超时不会自动重执行；不能把这描述成任何失败都能自动恢复。若后续引入 App 本地持久重发，需先规定远端身份、同一请求重试与用户发起新尝试的区别，再补崩溃回归。

还需设计执行记录的安全归档与容量恢复。Phase 4 的 Adapter journal 以 512 条为上限，Relay 回执和任务水印各限 4096 条；达到上限时拒绝继续接单，不随意删除去重记录。Phase 5 要提供明确提示和恢复路径，先验证旧请求不会因归档再次执行，不能仅提高常量或删除历史来掩盖问题。

备份覆盖专注、对话、记忆、Todo、工作归档和设置。API key 与 Agent 凭据不进入备份；恢复后重新配对，运行中的任务不会自动重执行。角色包默认记录 ID/版本，缺失时提示重新安装。

**验收：** 用户能解释并处理任务当前状态；不用手改 JSON 即可完成常用配置；在空目录恢复规定数据，导入失败不破坏旧数据；无模型和插件时仍可离线使用。

## 5.2 角色包与安装候选

沿用既有 `.fgopetpack` 安装器和 Phase 4 adapter 安装逻辑，补齐 GUI 交付缺口。现有 PowerShell/CLI 只作为开发、诊断和验收工具，不作为 Release 用户安装路径：

- 接回独立 SDK 分支的 art v3/人工布局确认基础，按当前实际 appearance/dialogue/persona/knowledge 合同完成确定性 builder。
- Python 与 .NET 使用相同合法/非法包 fixtures；相同输入生成相同哈希；验证安装升级失败回滚。
- 形成一份经过审核的玛修候选包；程序与角色资源继续分别构建、分别版本化，不嵌入原始剧情、未批准知识或可执行代码。
- 首版提供用户级 GUI 安装包；用户双击完成程序安装，不操作 PowerShell、PATH、CLI 或脚本。程序安装包包含 App 与所需 Relay/Adapter/插件载荷，但角色资源继续以独立 `.fgopetpack` 交付。
- 首次引导必须导入、校验并激活角色包；没有角色包时停留在角色包引导，不进入空白桌宠主界面。模型和 Agent 可以跳过，之后从设置页配置。
- 先明确一个主要 Windows/x64 环境与运行时安装策略；先做干净安装、升级、卸载重装，再决定是否扩大系统版本和 DPI 支持承诺。本机授权状态、生成目录和开发截图不得夹带进入安装物。

SDK 合同梳理、素材审核可与 5.1 独立推进，但 builder 不先于合同冻结；不再次重构已验收的画像和表情方案。

**验收：** 候选包可重复构建；干净 Windows 环境能安装并离线使用；用户可按文档配置可选模型/Agent；升级失败有恢复路径；程序和角色资源不混装。

## 5.3 小范围试用与发行门禁

- 先实际使用一个候选版本，记录具体失败和操作困难；只修影响日常使用、数据安全和承诺范围的问题。
- 复用已有 Phase 1–4 测试与人工证据，只对新增或受影响行为补测试；不为每个小任务重复全量测试。
- 候选冻结时执行一次构建、全量测试、安装 smoke、隐私检查和用户桌面验收；支持矩阵留下“已验证/未验证”的真实记录。
- 验证睡眠/恢复、App/Relay/Adapter 重启、任务去重、数据清除与备份恢复；设备范围以真实测试为准。
- 输出简短发行说明、已知限制、安装/卸载/恢复指导。公开上传发布仍是独立动作。

**验收：** 一个明确支持范围内的安装→日常使用→升级→恢复→卸载闭环可复现，核心数据不会静默丢失。

## 后移或不纳入首版门禁

| 项目 | 调整 |
|---|---|
| 应用类别感知 | 后移；需要新的隐私采样面，待当前功能稳定且用户确实需要时再设计 |
| 礼装收藏 | 作为内容增量候选，待正式 pack 与数据恢复稳定后决定，不阻塞首版 |
| 新的 Agent 羁绊奖励 | 后移；继续保持已验收的专注羁绊规则 |
| 第二个 Agent 平台 | 后移，先完成单一来源的可维护交付 |
| 云同步、自动更新、商城、移动端 | 不纳入当前 Phase 5 |
| 后台自主记忆写入、重做渲染/主题 | 不纳入当前 Phase 5 |

## 执行方式

每个闭环只保留“明确输入输出 → 实现 → 核心评审 → 必要测试 → 验收记录”。
独立工作可交给 5.6-luna / xhigh 子代理，返回根因、改动路径、测试结果与风险即可；不生成多层计划和重复评审报告。
桌面操作由用户执行并反馈。阶段成功以实际验收为准，不以旧计划勾选数量或代码行数为准。
