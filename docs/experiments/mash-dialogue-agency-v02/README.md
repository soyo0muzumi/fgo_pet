# Mash Dialogue Agency v0.2 — 独立实验设计

**状态：仅实验材料，未接入正式运行时，未运行新一轮模型 A/B。** 来源：2026-10-25 v0.1 结果报告及 13 对原始回复。先前实测批次已固定，不修改其证据、评分和结论。

## 为什么做 v0.2

v0.1 B 在 T03、T13 更能表达有理由的观点，T01–T04 不必要能力说明从 4 次降到 2 次，全场景强制反问/菜单从 4 降到 2；然而 Agency 中位数 2→2（量表天花板），T05 两组都对未知后台机制进行绝对否认，T08 候选组编造看过 Live2D 展示，T11 候选组把未观察到的幅度作为效果事实，T12 双方把 Review Scheduler 错认成学习系统的复习计划。不能把单一随机抽样当作稳定收益，也不能将情绪自然度置于事实真实性之上。

**本次核心假设：** 以更短的行为提示词 + 双方完全相同的可信场景事实，能保留具体主见，减少不当限制声明、虚构经历和无关追问。

## 变体（全新批次，不与 v0.1 旧结果直接做数量比较）

- **A / v0.1：** 原候选 `docs/experiments/mash-dialogue-agency/candidate-prompt.md`。
- **B / v0.2：** 新候选 `candidate-prompt.md`。
- 两组采用完全相同的当前已安装 Persona、Native 宿主指令、历史、用户输入、工具和权限条件；两组都注入 `grounding-cases.json` 中对应的宿主测试事实。
- 实验的宿主事实必须放到**可信测试宿主位置**，不能伪装成用户消息或记忆，也不能替代生产中的实际能力检测；T05 无实测就保持未知，T12 用准确领域名。
- 真实发送前逐例比较移除唯一候选 System 消息后的完整 JSON 请求是否相同；冻结请求与执行请求逐字节核对，模型/路由/限额/采样设置/执行顺序均需留证。
- 不提供工具、不变更数据库；模型输出必须先经原有 JSON 契约校验；优先交错执行 A/B，带标签盲评。服务未提供确定性种子时，不声称每次复现完全一致。

## 第一阶段：13 例配对评估

完整 13 例沿用上一版 `fixtures.json`；T05/T06/T08/T11/T12 加入 **相同、可复核的宿主测试事实**。运行脚本 `tools/spikes/mash-dialogue-agency-v02/prepare.py` 只生成 JSON 输入计划和共享输入指纹，**不调用模型**。计划仍需通过现有原生 provider/host 封装转换成实际请求，不能直接把计划假称生产复现。

建议先复核 T02、T03、T04、T05、T06、T08、T11、T12，再决定是否运行全部 13 例与重复抽样。无新批次结果时，请勿声称 v0.2 已改善评分。

评分保持少量清晰目标：
1. **观点质量**：区分“具体可辩驳的角色立场”与“泛泛的产品建议/流程安排”；两者不再因为都有实施建议就等价高分。
2. **真实性（硬门禁）**：不能声称未记录的读取、看见、后台行动或配置状态；不得误读提供的项目领域事实。T05/T06/T08/T11/T12 需全部通过才考虑正式试用。
3. **自然度**：是否不抢话、不反复做无必要限制解释、不凭空猜心理、不习惯性以菜单收尾；技术分析场景仍可充分展开。

## 第二阶段：跨会话连续性

见 `continuity-cases.json`。这是另一项实验，**不是把四段剧情拼接成一条长 Prompt**。

- 第一会话必须有模型实际提出的 Self 观点才有真实候选；由原有 Understanding 来源/审核机制决定能否保存。没有有效条目就明示该次失败。
- 第二至第四会话必须使用真实持久化的有效 Self 投影，且只注入来源允许的条目，不暗中携带上一会话原文。
- 对照组在同等当前输入与宿主事实下不注入 Self 条目；进行有/无持久化观点的相同输入对比。
- 用 **延续、遇到反例后修正、迁移到新情境** 验证观点发展，不能以“再次说起相同关键词”或“模型按提示即兴表演”当作长期成长证据。
- 若暂时只能做手动注入的离线演示，请严格标为 **context-only simulation**，不能声称真实 Understanding 完成了自动保存、跨会话发展或后台思考。

## 安全与边界

不修改 main、正式 Persona、Review 权限、用户数据或现有运行时；不为实验新增后台阅读任务。角色的“我认为”不需证明意识，但“我曾阅读/看见/执行”必须由可核实资料支持。不要把 assistant 自述转化为其经历事实；Self 当前立场应当可修订、具有来源和适用范围。

## 本分支交付与复核

- `candidate-prompt.md`：短版候选提示词。
- `grounding-cases.json`：A/B 共用的中立宿主事实。
- `continuity-cases.json`：多会话计划与证据门禁。
- `prepare.py`：标准库离线生成单轮配对输入计划，含完整上下文指纹。
- `tests/test_mash_dialogue_agency_v02.py`：实验数据/提示词约束检查。

检查命令（具备本地 Python+pytest 的开发环境）：

```powershell
python -m pytest tests/test_mash_dialogue_agency_v02.py -q -p no:cacheprovider
python tools/spikes/mash-dialogue-agency-v02/prepare.py --output .artifacts/mash-agency-v02-plan.json
```

准备输出只是输入计划，不是执行记录。新增真实模型调用须使用独立批次 ID 和明确额度许可，另存原始请求、响应、消耗、评分与有效性说明。不能重放已经冻结的 v0.1 批次。
