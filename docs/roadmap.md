## Next：首版发布后的稳定性工作

这些项目在 `0.1.0` 发布并收集真实使用反馈后再排期。`0.1.1` 定义为“使用体验与数据连续性版本”，优先解决当前反馈中最影响使用的派发可靠性、对话连续性和状态理解问题。

### v0.1.1 功能目标

#### P0：Todo / LLM 输出可靠性

- 固定并版本化结构化输出协议。
- 对模型输出执行 JSON/schema 校验，明确缺字段、类型错误和未知字段的处理方式。
- 解析失败时展示可理解的错误原因，并提供重试或编辑入口；不再只显示“无法检测模型输出”。
- 明确 Todo 创建、用户确认、交给 Agent、执行中、完成、失败和取消之间的状态转换。
- 防止重复点击造成重复派发，并在派发前显示最终确认信息。
- 评估 tool call 是否替代当前纯文本模板；只有在边界、权限和失败降级明确后才引入 MCP 或其他协议。
- 为正常输出、错误 JSON、缺字段、未知字段、重复派发和重试增加自动化测试。

#### P0：对话历史与数据连续性

- 保存多轮对话记录，并以稳定的 `conversation_id` 区分会话。
- “对话”页面增加历史会话列表、当前会话、打开历史会话和新建会话入口。
- 历史会话显示标题、最近更新时间和最后状态。
- 重启应用后恢复最近会话；历史消息加载失败时显示原因和恢复操作。
- 区分加载中、空状态、加载失败和正常消息状态。
- 将对话历史纳入数据导出、隐私清除和备份恢复边界。

#### P1：Agent 任务历史与恢复

- 查看已派发任务的历史记录，并按状态筛选。
- 明确区分等待、执行中、完成、失败和中断。
- Agent 断线、进程退出或应用重启后，任务进入可解释的恢复或待核对状态。
- 提供重试、取消或查看诊断信息的入口，避免任务长期停留在“执行中”。

### v0.1.1 UX/UI 优化主线

UX/UI 优化不是单独的视觉重做，而是围绕现有 WPF 桌面工具风格统一信息层级、状态反馈和交互规则。

- 统一“专注 / 今日 / TODO / 对话”的页面层级，减少重复入口和分散的事件反馈。
- 所有主要操作统一呈现初始、执行中、成功、失败和可恢复状态。
- Todo 采用“创建 → 确认 → 派发 → 执行 → 结果”的清晰步骤，避免用户误以为创建即已派发。
- 对话页面区分当前会话与历史会话，统一新建、切换、返回和加载操作。
- 角色包设置页重新组织安装、浏览、激活、卸载和包信息，减少无关信息干扰。
- 保持桌宠主体与表情层的 Phase 0 几何约束和 13px 偏移，不以 UI 改版破坏现有渲染对齐。
- 优化附着面板展开、收起、页面切换和主按钮反馈，避免按钮无反馈或突然不可用。
- 统一按钮、危险操作确认、错误提示和空状态文案；错误信息必须包含下一步操作。
- 所有可操作控件支持键盘访问，保留可见焦点，并补充 WPF AutomationProperties。
- 继续验证 Windows 高对比度、100%/150%/200% DPI 和窗口尺寸变化下的可读性与可操作性。
- 控制动画和状态切换的节奏，避免界面跳动；后续如增加动效，需提供关闭或降级策略。
