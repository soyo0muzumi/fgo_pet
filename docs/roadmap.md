# FGO Pet 后续开发路线

更新时间：2026-09-17

本文记录当前测试收口、后续产品方向与退出条件。路线是开发目标，不代表已实现、已验收或已获发布授权；历史计划、设计稿与详细验收证据保留为本地开发记录。

产品方向：以角色陪伴为主体，通过“能力”组织对话、语音、专注及后续情境感知和工作进度联动。功能配置易理解，日常操作仍有直接入口，离线基础工具不依赖模型。

## Now：v0.1.2 外部测试

v0.1.2 已合入本地 `main`，当前目标是生成 Windows x64 ZIP 并交给测试人员验证，不包含 MSI、自动更新或正式公开发布授权。

当前范围：

- 独立的桌宠、聊天与设置窗口，以及宽窄窗口下的任务面板。
- 对话历史、项目/意图上下文、Todo 提案和 Agent 任务状态。
- Agent 项目授权、停止确认、断线与未知结果恢复。
- Provider-neutral 语音模块、语音设置与播放生命周期。
- 模块化目录、共享 UI foundation 和对应自动化测试。

外测重点：

1. Windows 100%/150%/200% DPI、多显示器、中文 IME、键盘和高对比度。
2. 长对话、历史恢复、模型失败与重试，以及窄窗口布局。
3. 已含 Agent 的测试包保留项目授权、派发、停止、断线和恢复验证；后续普通用户入口撤下不代表历史包已停用，也不能掩盖遗留执行状态。
4. 真实 TTS 的播放、停止、长文本分段和临时文件清理。
5. 异常退出、重启、备份恢复和既有用户数据兼容性。

退出条件：每个确认缺陷都有复现步骤、严重级别和处理结论；P0/P1 无未解决回归；候选 ZIP 可重复生成并通过 manifest、哈希与隔离验收。

## Next A：v0.1.3 Maintainability / Architecture Recovery

v0.1.3 专注可维护性与架构恢复，暂不新增任何用户功能。以下是开发目标，尚不代表实现或验收完成。严格按下列顺序推进，每阶段通过边界与回归检查后再进入下一阶段：

1. **M0 Architecture Gate**：建立项目依赖 allowlist、模块所有权和例外收敛检查，让新增非法依赖在 CI 中失败。
2. **M1 Lifetime Foundation**：明确 Process / Module / Window / View / Operation 生命周期、application stopping token 和可等待的退出顺序；覆盖复制反馈关闭竞态 [#8](https://github.com/soyo0muzumi/fgo_pet/issues/8)。
3. **M2 Event + Diagnostic Policy**：统一提交后通知的逐订阅者隔离、隐私安全诊断、operation/correlation 追踪与后台任务监督。
4. **M3 Composition Root**：拆模块注册入口，将跨模块订阅和业务联动移入具名、可停止的 integration handler。
5. **M4 State Ownership**：ActiveServant、Focus 和 Attention 各有明确事实来源；ViewModel 只投影，不中转跨模块业务状态。
6. **M5 Todo Vertical Slice**：建立 `View → ViewModel → EditorSession → ApplicationService → Repository` 边界及窄执行保护契约；完成独立项目和模块单元测试，作为严格模块样板。
7. **M6 Focus / Speech / Agent boundary cleanup**：移除 Focus 对具体 SQLite 完成单元的依赖、Speech 对 legacy Core 的回依赖，并修复 Agent runtime host 生命周期；保留未纳入的 Agent supporting code 迁移债务。
8. **M7 Dialogue containment**：接入 Repository / Memory / Summary / Context ports，保持既有对话和工具语义，不修改长对话算法。
9. **M8 Architecture + lifecycle validation**：完整构建、模块/Windows/集成测试、故障注入、退出竞态、隐私诊断及模块替换检查。

退出条件：模块依赖和状态归属有自动化约束；注册代码不承载业务联动；Todo 独立项目及不依赖 App host 的单元测试通过严格模块门槛；后台任务可取消、可等待、可定位；通知失败不会静默阻断后续观察者；UI 生命周期竞态有回归证据；Dialogue 行为保持等价；适用完整门禁通过，Windows 实机验收单独记录。其余模块按实际证据标记部分完成，不要求本版本完成所有模块迁移。不得仅凭文件移动、链接编译或单元测试通过宣布模块独立。

不在本版本范围：新陪伴能力、视觉重设计、Agent 生命周期扩展、长对话算法/Context v2、数据库格式升级、MSI/自动更新及发布基础设施扩展。以下产品方向均放在 v0.1.3 之后；关联稳定性缺陷可随对应架构阶段修复，其他外测反馈单独分级，不自动扩大版本范围。

### 持续外测反馈管理

- 导致崩溃、数据丢失、凭据泄露、越权、任务错误重放或主流程不可用的问题优先分级；如需打断上述顺序，应单独说明阻塞证据并调整计划。
- 与状态归属、Todo 编辑或 UI 生命周期直接相关的确认缺陷纳入对应阶段，保留复现步骤和回归测试。
- 其他设置、模型、语音、DPI、IME、键盘、无障碍及多显示器反馈继续记录；不把新增体验改善自动纳入本版本。历史缺陷是否仍存在，以当前代码和复现为准。

### 后续发布准备（独立授权）

- 决定是否恢复 MSI、签名和安装器生命周期验证。
- 明确升级、回滚和用户数据保留策略。
- 形成可公开维护的发布说明、支持矩阵和已知限制。
- 在获得明确授权后再创建标签、上传附件或公开 Release。

退出条件：外测阻塞问题关闭；全量构建与测试通过；目标 Windows 环境人工检查有证据；发布包版本、Changelog、支持矩阵和哈希一致。

## Next B：能力设置与视觉整合

目标：沿用现有窗口与业务服务，将设置整理为“外观与角色 / 能力 / 通用与数据”，优先改善设置和聊天的观感与操作层级。

- 能力首页先承接现有对话、语音和专注配置，状态来自真实服务；不展示未开放能力占位。
- 保留桌宠点击收起/展开、悬停说明及拖动交互，统一按钮与状态外观。
- 采用柔和紫色、清晰文字与角色构图，先确认真实尺寸的设置与聊天设计，再统一主题、控件和其他页面。
- 优化轻量待办快速添加、完成与返回体验；不顺带扩展独立子任务、标签或复杂项目管理。
- 原 Agent 实现保留、冻结扩展，普通入口与自动启动/重连/后台活动分别收口；兼容已有活动和未知结果记录，不删除数据、不冒充完成。
- 保留深色主题和旧配置；不以视觉简化改变密钥、角色包、备份恢复与授权边界。

退出条件：一级栏目、子页返回与旧配置深链可用；设置和 Chat 在默认/最小窗口及浅/深色下通过用户视觉确认；DPI、IME、键盘和无障碍有实机证据；Agent 普通模式停用与历史恢复分别验证；适用自动化检查通过且无新增阻塞回归。

## Next C：主动陪伴最小版本

目标：让角色对用户行为和日常时间作出适度、连续的回应。

- 复用既有专注事件、角色反馈与表情链路，加入可控触发、冷却、去重和免打扰。
- 先使用本地时间与应用内确认事件，验证一个角色的小规模日常互动和短篇连续故事。
- 点击展开交互，忽略不惩罚；不抢焦点，不补发离线期间积压事件。
- 先从已有 Todo 与专注记录形成可编辑的工作学习回顾，区分计划、实际完成与模型建议。
- 故事持久化、包格式扩展、备份清除与旧包兼容在实现前明确；本阶段不默认读取其他应用内容。

退出条件：真实试用确认频率与角色语气；重复通知、重启、睡眠、时钟变化、切换角色、缺素材和写入失败不造成重复推进或数据错误；基础功能在模型不可用时继续运行。

## 后续验证方向

- **v0.1.4 — Conversation Context v2**：长对话、上下文压缩、滚动摘要重设计和预算分配留待下一版本；通过 v0.1.3 的 `IConversationContextProvider` 边界进入，不纳入本轮重构。范围和实现细节在该版本规划时确定。

- 情境感知：逐项评估指定应用运行/前台状态和游戏适配，按数据范围单独授权；不推断应用打开即为学习成果。
- 工作进度联动：原 Agent 可能作为真实状态接收的技术基础；开放前重新验证权限、状态与恢复，不默认增加执行能力。
- Live2D：独立进行单角色美术与渲染样板，验证交互、DPI、性能和静态回退，不阻塞基础 UI 与事件版本。
- 角色与灵衣：复用纯数据角色包，先完善单角色表情、日常反馈与故事，再扩展角色数量。

## Later：尚无版本承诺

- 自动更新。
- 角色包签名和可信来源机制。
- 更多语言与跨平台支持。
- 文件管理、浏览器/家庭设备控制和更复杂的 Agent 工作流编排；“能力”栏目不代表这些功能已经开放。
- 更多正式角色包及审核流程。
