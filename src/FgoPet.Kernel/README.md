# Kernel

Pure .NET foundation for current role identity, user profile and character preferences, semantic companion presentation, conversation execution, context lifetime, and process shutdown. `AppRuntime` owns the active role; `CompanionPresentation` publishes neutral expression and text state. Context lifetime and shutdown coordination own their respective lifecycle boundaries.

ConversationOrchestrator owns turn admission, authoritative message persistence, capability coordination and completion. ConversationModelTurn owns one model call, stream aggregation, bounded attempts, tool downgrade and connection-change fencing. PromptComposer, input token metering, model capacity resolution, original-message recall and transactional summary planning compile here against published interfaces. Original messages remain authoritative; summaries and token anchors are rebuildable. Token anchors are process-local and invalidate on route, input, output reservation or request metadata changes.

Concrete HTTP request policy, SQLite repositories, settings UI and dialogue presentation remain in the Dialogue implementation. Installed package binding belongs to Content. Kernel preserves the existing public namespaces and constructor signatures; it has no WPF, concrete provider, SQLite or feature implementation dependency.

Core persona and the active appearance overlay are mandatory, complete prompt blocks. History pressure returns an over-budget prompt to the existing compaction path rather than shortening character identity. A persona block exceeding the individual message limit fails explicitly; persona text is not automatically rewritten. Optional knowledge remains bounded.

Native context assembly collects fresh authorized plugin data before compaction, measuring the complete host/tool/memory envelope. It retains provider, message and transcript hard limits; after compaction the loop validates the final input budget before dispatch. Auxiliary summaries share the run budget, so final-response reservation is checked again after preparation. Fresh context is not persisted into the working transcript and is collected again on the next step; current reviewed memory versions take precedence over historical references to the same memory.

`ConversationContextDiagnostics` uses the existing `ILogger` Debug channel at preparation, compaction and dispatch boundaries. It emits UTC time, hashed run/source identifiers, numeric memory versions/revisions, persona presence and token estimates by category, never prompt bodies or tool payloads. Category estimates include independent request envelopes and must not be added together. Disabled Debug logging performs no diagnostic measurement; diagnostic failures cannot fail a request. These are developer diagnostics, not a new Chat UI or a persistent content log.

Every event published by an admitted `ConversationOrchestrator.SendAsync` carries one `ConversationUpdate.RequestId` (`request-` plus a GUID in N format). A trusted caller may supply a fresh GUID through the optional `requestId` argument before awaiting Send; otherwise the orchestrator creates it. The identity is captured in callbacks, including Native model stages, local replies, cancellation/failure and resumed Native delivery. It is not an authorization token. `ConversationId` can be reused across sends and `MessageId` identifies different messages, so neither replaces request correlation. Native `RunId` remains the durable execution identity returned in `ConversationSendResult`.

Production conversation runs allow 32 model requests and 64 tool calls per user send and opt into `RunBudget.ReserveFinalResponse`. These execution limits are separate from context capacity and per-request output tokens. Before the last available model request (or after exhausting the tool allowance), the loop removes offered tools and requests a final response grounded in existing observations, explicitly preserving partial coverage. A tool call in that final-only step fails without execution. Retries, compaction or an oversized batch can still exhaust hard limits; reserving a step is not an extra call or a guarantee that a provider will produce a valid answer. Other callers retain the default hard-budget behavior unless they opt in.

Host prompts identify the active persona as the desktop companion. Persona core and appearance text describe identity and expression without granting permissions or overriding host rules. The current user message is the turn's conversation or request; quoted material remains data. History, recalled sources, summaries and tool observations remain reference data rather than current instructions. All content envelopes escape delimiters and remain subject to the existing context budget and message limits.

Conversation recall enriches replies silently by default. Original-message recall, browsing and clarification require an explicit backward reference; current self-contained messages and questions about repeated clarification proceed to the normal reply. Clarification additionally requires multiple distinct selected candidates, an explicit ambiguity judgment, and a model-reported confidence of at least 0.85 for each selection. These scores are a conservative gate, not calibrated probabilities. Missing confidence or multiple search hits alone never trigger a history choice. Reference detection is deliberately conservative: unrecognized wording falls through to normal conversation.

`AgentRunCoordinator` provides a separately hosted native run loop: conversation admission, serial tool queues, bounded model/tool reservations, metadata events, cancellation and checkpoint compare-and-exchange. `IAgentRunStore` commits counters, intent, cursor and journal together; failed commits fence the writer. Completed step checkpoints retain bounded execution evidence separately from semantic conversation history. `IAgentModelStep` reserves each actual attempt through `IModelRequestBudget`. Typed skill, context and observer contributions are captured by the immutable plugin catalog; `AgentContextAssembler` applies provenance checks and measures assembled context through `IAgentModelInputBudget`. Tool execution commits intent before invocation and rechecks host resource authorization. Command tools default to denied without a host policy. Dialogue owns the protected SQLite run-state adapter and startup interruption closure. Approval/question UI presentation remains pending.

`NativeConversationRuntime` now supplies the host admission owner to `ConversationOrchestrator`, preserving trusted scope and generation across waits. Summary calls share the durable Run model budget. Semantic history and private tool transcripts remain separate. Final publication uses the Dialogue acceptance ledger; waiting returns a Run ID and a waiting status rather than completion. The frontend approval/question bridge is deferred: production registration omits `user.ask` and Command execution remains denied. Normal shutdown awaits cleanup; synchronous container disposal signals cancellation without blocking the UI dispatcher.

Native protocol and runtime checks: `dotnet test tests/FgoPet.Agent.Tests/FgoPet.Agent.Tests.csproj -c Release`. Synthetic providers and effects do not establish real-provider or product UI acceptance. Durable delivery and recovery checks belong to Infrastructure and App tests.

Native provider output ending with `length` fails as `MODEL_OUTPUT_LIMIT`, including incomplete tool calls. Conversation delivery explains the output limit or exhausted run budget and suggests a shorter or smaller request; it never publishes a partial final or automatically replays tools.

Same-conversation sends rehydrate available terminal tool calls and results from the existing protected run store, scoped by role, project, conversation and original user message. Historical call IDs are namespaced and registered as already used; historical calls are evidence, never queued work. Original arguments, results, statuses, timestamps and source identifiers are retained separately from semantic Chat messages. Missing results remain explicitly unknown/unexecuted. Intermediate assistant prose was not checkpointed and is not reconstructed. This does not confirm long-term memories or grant tool permissions; a current page may still need rereading to check freshness.

`ConversationSummaryService` also summarizes tool evidence. Completed historical turns use the existing summary projection and transactional coverage watermark. During a run the same service creates only a working-context projection; it never advances the watermark past the live user message. Compaction triggers near the existing token threshold or 512 KiB working-context size, preserves complete call/result groups and the current user/latest group, and charges the same model-request budget while reserving a final request. Source text is split by position to fit summary requests; failed or cancelled compaction leaves the projection unchanged. Production no longer silently drops old groups to fit. Protected originals remain under the store's existing retention/quota policy, not unlimited archival. A single oversized message or tool batch can still hit the unchanged protocol/transcript limits and fail explicitly.

Portrait rendering is a provider capability: Kernel exposes `IPortraitBackend`/`IPortraitController` contracts. The Kernel references Extensibility, which publishes Platform contracts, and standard logging abstractions.

Validation: run the relevant Kernel, Dialogue, Windows, and EndToEnd test projects under `tests/`, plus the architecture gate for dependency changes. These checks do not replace real-provider or device acceptance.

Each ConversationOrchestrator send captures one immutable RequestId for its event publisher, including Native and local capability replies. Callers may supply the GUID before starting a send; events never derive their identity from mutable current-request state. This identity is presentation correlation, not authorization or persistent run identity.
