# Offline local reference token metering

Non-production executable. It never registers the local counter in product composition, reads credentials, starts product plugins, or calls a model. Run only against synthetic isolated state. It uses current App registration, source Persona, complete tool descriptors, conversation orchestration and input guards through the existing compiled test fixture. Tool effects are synthetic and explicitly bounded.

The explicit arguments are an existing Python executable, `reference_worker.py`, an already available asset directory, and a new local evidence directory. No package installation, model weights, downloads or runtime discovery occur. The asset directory must match the worker's pinned manifest, both official revisions, tokenizer/template hashes, installed `tokenizers` 0.22.2, special tokens and ten golden encodings. Missing or changed assets are unverified. Add `--expect-unavailable` for the negative asset case; it verifies conservative fallback through the same host paths.

The worker loads once before host execution. Request bodies and rendered prompts exist only in memory and anonymous pipes; evidence contains counts, timing, hashes and fixed result metadata. Its blocked socket APIs are a defense inside the reviewed process, not an OS network sandbox. The HTTP and credential dependencies of the application fixture separately reject use.

Before starting Python, the host checks the fixed worker SHA-256. It also requires the fixed worker and policy hashes in the startup handshake; a worker cannot nominate a new policy by reporting its own hash. Changed worker bytes are rejected before process creation. Missing or changed assets keep the counter unverified and the existing conservative fallback available.

The reference policy takes the largest complete official encoding across chat and thinking efforts 50/75/100, retaining reasoning fields. Both input and actual wire hashes and the immutable policy hash must match before `LocalReferenceRequestTokenMeter` accepts a count. Unknown routes, revisions, metadata/wire policy, output settings, invalid counts or unavailable counters retain the full conservative estimate. Exact-envelope provider usage has precedence; local counts never create usage anchors. The cache retains at most 64 hashes/counts and clears on invalidation, with no content retention.

Evidence distinguishes meter latency from diagnostic hashing/serialization, checks ordinary and Native complete catalogs, a read continuation with transient reasoning, over-budget refusal, missing assets and counter loss. It does not sign H1/H2, change the 16k/2048 limits, prove provider-side token usage, or authorize a real batch. Product packaging, availability of a reference runtime and assets, and any production activation remain unverified.

`PipeCounter.cs` is shared as linked test source with the Understanding validation driver. Its `offline-reference-formal` command checks the same reference counter through actual synthetic trial precharges, review and classification, while rejecting this injection for live hosts. Each tool starts and owns its own warmed counter; neither changes product registration.
