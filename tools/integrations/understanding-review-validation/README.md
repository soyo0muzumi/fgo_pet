# Understanding Review validation

Non-production preparation probe, compiled only into `FgoPet.App.Tests` by an explicit source link. It has no application registration, provider connection, background scheduler, write tool or executable entry point. Tests use temporary SQLite databases, synthetic originals and a typed substitute; production history and settings are not opened.

`ReviewPipelineProbe.RunManualAsync` composes the existing Understanding manual-preview admission, attempt reservation and commit with Dialogue's published original/source-version ports. The host selects exact source snapshots and anchors. The probe freezes that selection, reads and verifies the selected originals, then supplies an immutable request to one substitute invocation. That request carries a host-owned `EnsureCurrent` fence for adapters to invoke after preparation and diagnostic callbacks, immediately before dispatch. Final state validation and candidate routing remain owned by `UnderstandingService`. Precancelled calls return a cancelled Task with the original token; producer cancellation exceptions propagate unchanged.

The probe accepts at most eight originals and 6,000 Unicode scalars in total, rejecting oversized material whole. These are local probe input bounds, not model token estimates or changes to production context/output limits. Both source versions and policy generations are checked around material reads. Already committed receipts replay without reading bodies or invoking the substitute; a failed or cancelled reservation is not retried or refunded.

All proposals use the current owner's review-required policy. The existing manual-preview API does not attest body coverage, so this probe does not establish automatic bounded routing. Typed substitute output is not evidence of JSON parsing, actual provider metering or model semantic quality.

Diagnostics contain only time, a hashed operation correlation, fixed stages and safe codes. They omit original text, proposal content, identifiers, exception messages and parameter values. A failing diagnostic sink does not change the operation result. Original cancellation exceptions propagate through the existing owner.

Verification is `ReviewPipelinePreparationTests` in `tests/FgoPet.App.Tests`, together with existing Understanding policy/settings/privacy regressions. Use Release, `-warnaserror`, and an absolute isolated `ArtifactsPath` when preserving frozen test/application outputs. The tests neither sign H1/H2 nor demonstrate the formal M2 worker or real Review adapter.

`ReviewModelExchangeProbe` adds an optional protocol-level substitute using the published `IChatProvider`, `ChatRequest` and `ModelStepAggregator` contracts. It has no concrete provider, endpoint, credential access or application registration. Tests supply an in-memory provider. It creates one no-tools request with a fixed schema instruction and one user-role JSON data message; selected originals remain data. It does not call `ConversationOrchestrator.SendAsync`, run a tool loop or generate a draft. The output reservation stays 2048. The existing conservative meter checks this isolated request against 16,000 input tokens; this is neither a calibrated target-model count nor the complete production Persona/route envelope.

Without selected revision targets, the response remains one exact object with `schema: 1`, the echoed request binding and a `proposals` array. Every proposal has exactly `domain`, `kind`, `subject`, `content`, `conditions` and nonduplicate `sources` aliases. Unknown or duplicate fields, undeclared aliases, numeric enum names, markdown wrappers and mismatched bindings fail whole. IDs, scope, original versions and supplied-body coverage come from the host. The parser produces proposals, never approval, permissions or effective state. An empty proposals array is the explicit no-change result.

The exchange consumes and closes the whole stream, rejects length/incomplete/tool output, and requires positive final usage within its request limits before parsing. It performs no format repair, retry, refund or model discovery. A primary read/cancellation error survives a simultaneous close failure; a close failure on its own fails the exchange. Logs retain the existing metadata-only schema and allow only exact safe error codes. Supplied coverage in the returned evidence is not wired into the existing manual-preview commit: persisted candidates still have null coverage and remain pending until exact approval. The baseline exchange alone has no request ledger or dispatch lease. The separate contracts below remain offline only; automatic scheduling, semantic classification proof and production dispatch are absent.

An explicit `ReviewProbeTargetSelection` binds the same role/project, target ID and exact revision. The probe reads only that target through the owner's authorized historical query, which excludes pending, rejected, retracted and resolved records. The independent dialogue-use grant is required by that published query. The snapshot retains correction, conditions, source attribution, dates and lifecycle; it is rechecked after preparation and diagnostic callbacks. Selected targets are reference material, never new original roots. A missing, stale or unauthorized target refuses the operation rather than dropping it silently.

Selected targets opt into an isolated `schema: 2` instruction with a required proposal `target` field: null for creation, or a request-local `t` alias for one selected revision. The host supplies actual target ID/revision and rejects duplicate revisions of the same target. The existing schema 1 instruction and request shape remain unchanged. Target snapshots participate in the request hash. Updates still enter the existing pending replacement flow: exact approval rechecks the target revision and only then retracts the prior entry. Stale output cannot overwrite a newer correction.

Each original read seals `ReviewReadProof` with its exact source snapshot, full Unicode-scalar range and SHA-256 of the supplied text. The exchange checks those proofs and the host's operation hash before provider entry. `ReviewCommitContractProbe.Validate` checks the complete request binding, returned coverage, original roots and selected target revisions and prepares immutable evidence for the owner's coverage-aware `Begin` port. Results cannot be reused with a different operation or request. Tests can validate a ticket without applying it; this is not another commit path. The existing `PreviewAsync` API still receives only proposals, so its persisted coverage remains null and automatic BOUNDED routing is not established. Model-supplied coverage is forbidden. Changed bodies, partial ranges, foreign sources and missing/duplicate proofs fail whole.

On error paths, tests establish exactly one `DisposeAsync` attempt and preservation of the primary exception. A failed dispose is not evidence that provider resources were successfully released.

`ReviewDispatchLedgerProbe` is a separate temporary SQLite contract, accepted only at a dedicated `fgopet-review-dispatch-*` temporary directory and `dispatch-probe.db`. Task, batch and trial limits are registered and immutable. An immediate transaction checks all three limits and inserts one unique, permanently charged request row before handoff. All row states consume quota; duplicate requests, errors, cancellation and missing usage never refund it. Reopening connections preserves counters without disturbing live reservations. Explicit recovery changes unfinished reservations to Unknown and must run only after the old session has stopped; it never clears counters or grants authorization. This is an instance-recreation regression, not an application/process crash acceptance test or a production migration.

`ReviewDispatchAuthorityProbe` starts unauthorized. One-use permits bind the batch/trial/request, operation and input hashes plus scope, route and policy generation. Authorization updates and synchronous dispatch handoff share one authority lock. If revocation wins, handoff and charging are refused. If handoff wins, its precharge remains, revocation cancels the linked token and stale results are refused. A cancellation between precharge and handoff can conservatively consume quota without dispatch. `Configure` updates authorization and requests cancellation without waiting for callbacks, so a cancellation callback may revoke again. The owning `RunAsync` drains those callbacks during finalization before disposing its linked token source; primary work exceptions survive callback/accounting failures. Final diagnostics precede the last current-state check.

This linearization covers cooperating callers of the same isolated authority and the invocation of the supplied start delegate. It does not prove a remote HTTP send instant, cross-process authorization, or atomicity with independently changed production owner state. The adapter must still use the host current-state fence; real route/source/target binding and production owner integration are not installed. Wrapping the existing in-memory exchange proves budget rejection before provider entry, pending isolation and existing stream/cancellation behavior, without changing the frozen request templates, limits or retry policy.

Dispatch logs contain only timestamp, request-hash correlation, fixed stages and safe codes. Ledger rows retain full request/operation hashes, a complete binding digest, quota scope hashes, accounting state and optional token counts; no original IDs, material, parameters, exception values or credentials are persisted. Request correlation joins to its ledger row; the operation hash joins requests belonging to one host operation. Verification includes the `Dispatch_` regressions in `ReviewPipelinePreparationTests` plus the existing related owner and architecture suites. These contracts grant no real-model budget, register no production service and do not close H1/H2 or formal M2.
