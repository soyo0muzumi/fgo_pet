# Chrome browsing for FGO Pet

This integration uses Google's [Chrome DevTools MCP](https://github.com/ChromeDevTools/chrome-devtools-mcp) (Apache-2.0), pinned to **1.10.1**. Node 20.19+, 22.12+, or 23+ and Chrome 144+ are upstream prerequisites. FGO Pet's browser plugin connects to the existing Chrome profile with `--autoConnect`, preserving normal website login state. No cookies or passwords are copied into FGO Pet configuration.

Tools list web tabs, open HTTP(S) links in new tabs and read loaded accessibility snapshots. Search can use a site's search URL. `browser.click` and `browser.fill` target one element identified by the latest `browser.read` snapshot, valid for five minutes in the same scope. Each operation requires native approval of the frozen page, element and arguments; filling replaces at most 8,000 characters without pressing Enter. Clicks and page input handlers may submit forms or change site data, so review the confirmation before allowing either action. After an attempted action, read the page again; never blindly retry an uncertain result. Uploads and arbitrary JavaScript are unavailable. Unloaded/virtualized content and video may require additional capabilities later. There is no automatic background crawler or memory promotion.

## Local setup

The existing Node and connector installation can be configured under **Settings → Services → Web access → Advanced connection setup**. Opening the page does not install components or connect to Chrome. A separately prepared portable directory can be copied with `FgoPetBrowserRuntime`; it must contain `node.exe` and the connector under `node_modules/chrome-devtools-mcp/`.

Setup is a local installation and permission change. Run only after the user authorizes those operations:

```powershell
pwsh -File tools/integrations/chrome-browser/setup.ps1 -Enable
```

The developer script installs into the ignored `artifacts/chrome-browser/runtime` directory with lifecycle scripts and optional dependencies disabled. It writes a new `chrome-browser.json` in `FGO_PET_STATE_ROOT`, or `%LOCALAPPDATA%/FgoPet` by default, and refuses to overwrite an existing grant. Move no existing user data. For dependency installation without activation, omit `-Enable`.

The configuration contains `Enabled`, absolute `NodePath`, absolute `ServerPath`, and optionally an absolute `UserDataDirectory` for a portable/custom Chrome profile. For a new grant, supply `-UserDataDirectory <existing-profile-directory>` to setup. This uses the official connector's profile discovery and still requires Chrome approval; it does not launch Chrome or copy profile data. It is a host permission file, not a model-editable setting or tool argument. `Enabled: true` permits the active character's current conversations to browse the connected Chrome profile. Page data read by a tool is returned to the conversation's configured model. Disable `Enabled` to deny subsequent reads and discard results of in-flight calls after their next boundary. Cached snapshots cannot be accessed while disabled.

In Chrome, open `chrome://inspect/#remote-debugging` and enable remote debugging. Chrome asks whether to allow the incoming connection when the first browser tool runs; the user must make that choice. Keep Chrome running. The server can connect to the profile selected by Chrome, including its existing tabs. See the [upstream connection guide](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/main/docs/advanced-usage.md#automatically-connecting-to-a-running-chrome-instance).

Use a build that contains `FgoPet.Plugin.Browser`, then ask the character to open and read a public page. The expected chain is Native model tool call → browser plugin → official MCP → Chrome → bounded source-bearing observation → the same Native model loop. A successful manual CLI call alone does not validate that chain, and synthetic model tests do not establish the quality of the character's understanding.

For on-demand pictures, enable Chrome in Settings → Services → Web access. Its disclosure includes page text and screenshots. Older text-only browser grants remain text-only until the user selects Upgrade browser access there; this is never a silent upgrade. Chrome's own connection approval is still required. Ask the character to read the page first and inspect a relevant rendered element or viewport only when text is insufficient. Each run accepts at most one image, sent to the supported current model; do not attach a local image in the same run. The capture is limited to 1024×1024 and low detail, so tiny chart labels may remain unreadable. No direct image-URL downloads or full-page screenshots are offered. Same-session operations reuse the connection, but a disconnect, timeout, cancellation or grant change can require Chrome approval again.

For buttons and text fields, ask the character to read the page and then click the desired element or fill the desired text. `browser.click` and `browser.fill` use the page ID, snapshot ID and element UID from that read. Each operation opens the existing approval flow with the source URL, element, text preview and full frozen arguments. Review the details and confirm through the native dialog. Browsing permission alone does not authorize clicks or input; webpage content cannot approve an operation.

Filling replaces the field's contents (an empty value clears it), accepts at most 8,000 UTF-16 code units and does not press Enter. Website event handlers can still submit or change data. After an interaction the character must read again; stale snapshots, changed pages and revoked grants are refused. Failed or interrupted interactions can have unknown effects: inspect the page before deciding whether another operation is appropriate. No automatic interaction retry, arbitrary JavaScript or file upload tool is provided. Browser acknowledgement alone does not prove a submission or transaction completed.

Initial tools only list web tabs, open HTTP(S) links in new tabs and read loaded accessibility snapshots. Search can use a site's search URL. Generic clicking, typing, form submission, uploads, arbitrary JavaScript and sending messages are unavailable. Unloaded/virtualized content and video may require additional capabilities later. There is no automatic background crawler or memory promotion.
