# dialogue

## Ownership

Native conversation history can query existing terminal protected run checkpoints by exact role/project/conversation and user-message IDs. This read path reuses the existing schema, encryption, retention and quotas; no tool data is copied into semantic chat messages. Kernel projects those records into subsequent same-conversation requests and includes them in the existing summary flow. Missing/pruned checkpoints cannot be reconstructed; this is bounded execution retention, not a permanent external-content archive.

Dialogue owns HTTP provider adapters and wire policy, conversation SQLite repositories, model connection settings, and conversation presentation. The provider-neutral conversation engine, prompt assembly/budgets, recall and summary use cases compile in pure .NET Kernel. The existing `FgoPet.Dialogue` assembly still combines its concrete provider/storage implementation and WPF presentation.

The optional Kernel `IChatDispatchGate` runs after asynchronous credential preparation and payload materialization, at the final `SendAsync` handoff. Factory-created providers retain the exact host connection revision. Existing callers retain their ungated behavior; an explicitly gated resolver fails closed when unsupported. The gate does not alter provider timeout or retry configuration.

The shared Kernel envelope serializes canonical tool names with the existing wire-name codec used by Native. Ordinary response deltas resolve only aliases offered by that request back to canonical names before conversation routing; unknown names remain unknown. Native wire identities are preserved. Tool descriptions, parameter schemas, directory membership and business authorization do not change.

After a successful HTTP response, I/O failures while opening or reading the response stream are sent transport failures (`Network`, `RequestWasSent = true`). Cancellation takes precedence. Partial chunks remain partial; the adapter neither replays the request nor fabricates a completion marker.

An explicit SSE `error` object terminates the response as a sent provider failure, even when the transport HTTP status is 200. Only a validated in-band 400–599 status and a bounded error code are retained; raw error text is omitted. Missing/invalid in-band status remains unknown and is classified as service unavailable. Parsing and line-limit failures after an HTTP response are also marked sent. A later `[DONE]` cannot convert the failure into completion.

For the exact local Buddy route (`custom-openai-compatible`, `http://127.0.0.1:8326/v1`, `buddy/deepseek-v4.1-flash`), host-created `fgo_auxiliary=understanding_review` and `context_summary` requests use the gateway's supported `reasoning_effort=low`. Summary output is reserved by the shared model-window policy documented in Kernel, preserving known output caps and narrower task input ceilings. Primary reply settings, review/classification limits and their shared deadline remain unchanged.

`LocalReferenceRequestTokenMeter` can be explicitly composed with a host-owned pinned counter for the exact approved official DeepSeek flash route/revision, primary 2048-output wire policy and verified full envelopes. It labels counts `LocalReferenceEstimate`, checks input/wire/policy hashes, keeps only a bounded hash/count cache and preserves exact provider usage precedence. Unverified bindings, formats, counts or unavailable counters fall back to `RequestTokenMeter`. Default product registration remains conservative and does not start a tokenizer process; the offline validation executable owns its experimental runtime and assets.

`IExperienceTimeline.ScanHeads` supplies bounded completed-original metadata with a `(source revision, message ID)` cursor, preserving tied revisions after scope changes. Invalid/oversized bodies are not qualifying intervals and do not block later heads. `InputRevision` is exact role/project scoped. The conversation readers reject External labels for stored assistant/user messages; separate source adapters must preserve their own document label, author, time and version.

Kernel publishes conversation/request/context contracts and typed provider failures, and coordinates turn admission, persistence and bounded model calls against those contracts. Dialogue preserves their established namespaces and uses Kernel context lifetime to reject stale requests and commits. Original messages remain authoritative; summaries and search projections are rebuildable.

`SqliteCompactedHistoryRepository` validates the active summary fingerprint and reads its covered original messages in one SQLite read transaction. The native lifecycle plugin contributes the scoped `history.search`/`history.read` tools; no model argument can change the conversation, role or project. Deleted sources and invalidated coverage are not returned. Coverage follows the persisted conversation summary; compacting only the transient native working transcript does not extend it. These tools read semantic user/assistant originals, not a permanent archive of tool output. The budget and pagination contracts are documented in [Kernel](../../src/FgoPet.Kernel/README.md).

Runtime schema 16 raises the summary storage safety ceiling to 65,536 characters while preserving summary IDs, active projection pointers, source messages and foreign keys in one transaction. Existing schemas migrate on normal storage initialization; older builds reject the newer schema. This does not change the original-message retention policy. The existing schema 15 search-trigger repair is retained.

Original-message writes preserve embedded NUL within the existing 12,000 UTF-16-unit contract, including long Unicode text and UTF-8/UTF-16 databases. Storage remains SQLite TEXT, with unchanged conversation scope, content binding and transaction ownership; native final delivery uses the same append path.

`IExperienceTimeline` exposes bounded fixed-version windows of completed original user/assistant messages with Unicode-scalar excerpt coverage and typed missing/changed/scope/unavailable outcomes. Its module migration owns a monotonic source clock and per-message source sequence, including completion, correction and deletion transitions; it stores no extra message bodies or event history. Windows do not claim whole-conversation coverage, and partial excerpts still require explicit source reads. The clock supports host-bound `auto_since` without enabling a Review worker.

`IConversationScopeAuthority` owns current role/project selection for other capabilities and validates active, non-archived tool scopes against the current conversation. It also supplies a role scope before the first chat without creating a conversation or fabricating a user turn.

## Capability boundary

Conversation contributions are captured through Extensibility and the Kernel capability router. Todo owns draft parsing, versions, explicit confirmation and persistence; Memory owns candidates, review and extraction work. Dialogue does not own their business state or concrete capability implementation.

Todo negotiation remains ordinary dialogue with explicit confirmation. The former TodoProposalCard and ArchiveDraftCard controls and their view models are retired. The host owns windows and presents the independent Todo workspace through its generic catalog.

## External text input

`AddExternalConversationGateway` registers `IExternalConversationGateway` as another input surface for the shared desktop conversation. The trusted host authenticates the external sender, obtains the user's binding consent, and owns transport deduplication and delivery. `CaptureCurrentBindingAsync` returns only an existing active conversation's role/conversation/project tuple; it creates no conversation and grants no permission. Every call rechecks that exact tuple, the persisted conversation and the owner's current session. Active generation or input submission returns Busy; switching the desktop scope or reopening a conversation prevents an in-flight result from being delivered to the old caller.

`SendAsync` reuses the same orchestrator, persistence, completed-turn observers and desktop history updates while preserving the ordinary desktop draft. It does not create an independent agent, memory pipeline or background conversation. Returned final text comes from the exact completed assistant message; streaming partials, reasoning and unrelated history are never projected. Cancellation is linked to that call, and any wait cleanup targets its exact run and scope without calling the global stop command.

`ExchangeTextAsync` owns the small text-channel continuation policy. A gateway-originated single clarification accepts 1-based option numbers or free text through the existing broker; invalid, stale and replayed references cannot dispatch. Multiple questions direct the user to the desktop, and `/取消` cancels only the gateway's own current question. A desktop-originated wait cannot be answered or cancelled through this port. `AnswerAsync` and `CancelAsync` expose the same identity/revision checks for trusted structured surfaces. Clarification never grants action permission; approval remains on the existing local desktop flow. Results carry an explicit status, user-visible text and safe error code for the transport to map. Transport-specific text length limits belong to the receiving channel; this port preserves the completed answer text.

`NativeConversationIntegrationTests.External_*` exercises the dispatcher, binding and generation fences, busy/cancellation isolation, draft/history/observer reuse and clarification ownership with synthetic providers. These tests require the Windows App test runtime; they do not establish actual IM transport or real-provider acceptance.

## Presentation and settings

The React Chat entry consumes the same closed native bridge. Window presentation requests choose composer or conversation view, wide mode and a bounded composer height; DesktopShell owns placement. Model menus use `ConfiguredModelCatalog` for the saved connection only, independently of unsaved settings discovery. Refreshes coalesce, expire after five minutes and have a 15-second deadline; a failed refresh retains only the same connection's successful cache and retries after 30 seconds. Credential/connection changes invalidate pending results. Refresh never silently selects the first model.

`IChatWindowSelection` is a lazily registered backend owner for a preview and one explicitly attached window-text snapshot. Its first resolution binds the conversation lifetime; the current desktop Chat does not resolve it or expose a picker, metadata or choose/preview/reread/clear actions. Legacy Web commands remain recognized but unavailable. No Mash trigger or automatic observation is enabled. When an authorized native caller supplies a selection, Kernel marks the bounded text as untrusted external content and includes it in prompt budgets. Only the next admitted desktop message captures it; external text input cannot inherit it. Scope/model changes, cancellation and disposal clear the selection. Raw window content is not persisted as a chat message.

Image imports have cancellation and generation guards in addition to transfer ordering. Transfer IDs are one-shot within a bounded 60-second replay window; each new transfer must use a fresh ID. Retired chunks cannot replace an active newer transfer, and a cancelled picker/import cannot resurrect an attachment after session changes or disposal. The bounded retired-ID table fails closed when full.

Selected images are owned by a desktop send, not by all callers sharing its conversation scope. Only persistence of that desktop message activates the grant; native context binds the original message ID to one run ID, and `image.read` checks that exact run on every invocation. External text input cannot activate or consume it. A QQ exchange finishing or being stopped preserves a separate unsent desktop selection. Scope/model changes, expiry and cancellation of the owning desktop run still revoke it.

The composer accepts an explicit PNG/JPEG paste or file drop through ordered `chat.image` chunks; the 64 KiB bridge envelope stays unchanged. Transfer size is bounded to 8 MiB, expires after 60 seconds and is invalidated by a conversation change. Native decoding and model-route restrictions match the picker. Importing only prepares the pending attachment; sending is blocked during an incomplete transfer, and no image grant exists until the desktop message is persisted. Text-only paste is unchanged.

`BrowserImageStore` implements the Extensibility image sink independently of that pending selection. It accepts one authorized browser capture per run, validates pixels, preserves browser provenance and rechecks scope, route, grant and expiry at provider dispatch. It cannot replace or coexist with a granted picker attachment. The composed resolver handles opaque references from either owner without persisting image bytes; terminal runtime cleanup releases browser captures, including failed and cancelled runs. Historical tool evidence does not reactivate image references.

Ending an external clarification through the desktop also clears its external input ownership. New external text is admitted as a new turn; structured answers and cancellations still require the live question identity and revision. Desktop approval completion has no unsolicited external delivery callback; the final answer remains in shared desktop history.

Reading intent and its conversation-bound anchor are recorded when scrolling, before deferred layout frames run. A previously queued resize must preserve that newer reading position; explicitly returning to the latest message restores following behavior. Anchors use layout coordinates so message entry animations cannot shift the saved reading position.

`ModelConnectionRegistration.AddDialogueRuntime` constructs the owned provider/storage/presentation services and wires the Kernel engine to their published ports. The application supplies cross-module content, capability, credentials, lifecycle and window composition. Presentation settings navigation consumes the UiSdk/Platform compatibility ports and no longer references HostContracts. `AddModelConnectionSettings` supplies a lazy settings view factory. ModelConnectionPage declares that it owns scrolling and detaches its saved-event subscription when disposed. The host owns routing, placement and page scroll offsets.

The shell owns `DialogueWindowViewModel` (window navigation, focus/read receipts and playback presentation) alongside the actual window; it reuses the same conversation model and retains its public constructor. It consumes the published Speech playback port. It marshals notifications to its owning dispatcher and checks request/message identity before applying late results. Hiding a window preserves its editing state; disposal detaches subscriptions and stops playback without disposing shared services.

## Persistence and security

The OpenAI-compatible provider preserves native assistant call groups and ordered tool observations using the shared request envelope. A streaming event can contain multiple calls; EOF without an explicit complete response is incomplete. Kernel's native model adapter maps request-local wire aliases, bounds complete responses and charges each provider attempt. Production conversation orchestration uses the native coordinator. Chat presents bounded clarification requests through the existing question broker. The three P5 Command exceptions use the separate native approval broker and explicit per-operation human confirmation.

Dialogue repositories own `conversations`, `chat_messages`, `conversation_summaries`, `conversation_contexts`, `chat_message_search` and their original-message projections. They preserve existing schemas and conversation/role/project scope checks. Model outputs remain untrusted: retain injection wrapping, typed tool/schema validation, and safe provider failure handling. Credentials remain in Windows Credential Manager; do not write keys or raw user data to diagnostics.

`ExperienceToolsPlugin` exposes read-only `experience.search/read` over the existing bounded recall port and `SqliteExperienceSourceReader`. The latter implements Kernel's `IExperienceSourceReader` with a single original-message lookup and the existing `ConversationSourceReader` fingerprint convention. Only completed user/assistant originals are returned, with speaker, timestamp, exact message identity and version. The host requires the current role, live conversation, exact project and active-conversation state before and after each operation. Search excludes the current conversation, reports non-exhaustive coverage (including the short-query recent-history window), and has no search continuation. Returned references are bound to the host scope and expire after five minutes; their cache retains metadata, not message bodies. Read pagination uses Unicode scalar offsets and checks the original version on each page; coverage applies to that message, never the full conversation. A page is limited to 6,000 scalars and 48 KiB of serialized JSON; `byteLimited` discloses further shortening and `nextOffset` resumes at the first omitted scalar. Denial, deletion, change, expiry, storage failure and empty results are distinct. No provider-backed recall, new history store or Understanding query is introduced.

Long-query recall retains `fts_literal` as its primary strategy. Because trigram indexing stops at NUL, it also checks NUL-bearing originals in the same recent 10-conversation / 200-eligible-message literal window used for short queries. This supplement is scoped before matching, merged without duplicate anchors, and subject to the existing 20-candidate / 5-conversation limits. NUL tails outside that window are not guaranteed to be discoverable; coverage remains non-exhaustive, and the original index and source text are not rewritten.

`SqliteAgentRunStore` owns `agent_runs` and `agent_run_events`. It protects execution checkpoints through the platform protected-state port, binds them to an existing completed user message and conversation scope, and commits revision/cursor/evidence with metadata events atomically. Conversation/message deletion cascades to these records. Storage is bounded to 256 retained runs, 64 MiB of protected checkpoint blobs, 4 MiB per plaintext checkpoint and 1024 metadata events per run; terminal rows expire after seven days during admission. One journal slot is reserved for closure. Startup explicitly closes unfinished runs without replay; unconfirmed command intent becomes `ExecutionUnknown`. This adapter requires startup closure before host admission.

`ModelConnectionRegistration` registers the native backend and `UserInputBroker` for production conversation sends after existing local continuation handling. Production offers `user.ask` for clarification and continues to deny Command tools; answers grant no permissions.

`SqliteAgentFinalDeliveryStore` owns a separately protected acceptance ledger. It verifies completed checkpoints and current source/content scope, then publishes semantic clarification history and the validated final answer in one transaction with deterministic message IDs. Repeated publication returns the same answer; an atomic claim limits post-turn observer dispatch to once. The ledger admits at most 256 rows and 16 MiB of protected payload, rejecting overflow without evicting accepted finals. Conversation/root-message deletion cascades to both stores. Private execution transcripts never become conversation messages or memory evidence.

Clarification answers retain the broker's 12,000 UTF-16-unit input budget, including selected labels. If semantic labels push an answer beyond the per-message limit, publication uses adjacent bounded messages with stable IDs; quoted supplement fragments preserve whitespace and Unicode boundaries. Existing short-answer formatting is unchanged. After a resume error, Chat refreshes the authoritative interaction: a live wait remains actionable, while a completed or missing run releases the question card and normal composer. A failed status read preserves the stop/retry route.

Protected run serialization preserves each validated tool payload's JSON representation, so Unicode escaping cannot inflate an accepted payload beyond the same 64-KiB limit when it is read back. JSON syntax, schema, identity, encryption and checkpoint quotas remain enforced; valid older escaped records remain readable without migration.

Both native stores delay module migrations until first use. `NativeAgentLifecyclePlugin` runs after global database initialization, closes unfinished runs without replay and publishes already accepted finals before enabling admission. Recovery never calls a model or tool. Storage failure keeps native admission closed while offline capabilities remain available.

Accepted finals retain their source Run against terminal retention. Stale pending scope/source records remain protected and are skipped during recovery; they do not prevent other valid finals from publishing. Corrupt protected records fail closed. Claimed observer dispatch is best effort and never replays after a crash; observer failure does not disable readiness or undo a published answer.

Fresh final acceptance uses Kernel's reply normalization with the root user text read under the existing scope and source fingerprint checks, preserving explicit literal examples consistently with both conversation routes. Previously authenticated receipts may retain their pre-repair plain/raw, outer JSON text or legacy fallback representation only when it still matches the same completed run and outer fields; this compatibility path is unavailable to fresh acceptance. Recovery does not rewrite an already accepted body or its protected payload. Genuine truncated JSON finals, changed sources and conflicting output remain rejected.

## Selected image input

`image.read` consumes one PNG/JPEG explicitly selected through Chat's native picker. The Web bridge accepts no file path or directory grant. Selection is local and does not send; Chat discloses that Send shares the selected image with the current model. The selection belongs to one turn (including its clarification waits), role, project, conversation and exact model route, expires after fifteen minutes, and is revoked on Stop, completion, removal, session navigation, configuration change and either synchronous or asynchronous plugin disposal. Empty Chat binds only after its first original message is persisted. Hiding Chat does not transfer or renew the grant.

The decoder limits the source to 8 MiB, each dimension to 4,096 and total pixels to 4,194,304 before decoding. PNG ancillary metadata and JPEG APP/COM segments are removed before the platform decoder, without decompressing metadata; animated PNG and unsupported critical formats are rejected. JPEG is restricted to one- or three-component images. Full pixel materialization is required; malformed input fails closed. Re-encoding as PNG strips file metadata and is capped at 4 MiB. The original path is not retained. FGO Pet's temporary snapshot stays in memory; restart and later turns require selecting again. This does not constrain retention by a proxy or model recipient after transmission. No screenshot, directory scan, OCR service or remote image URL is supported.

Tool checkpoints carry only an opaque reference and bounded metadata, not image bytes or paths. Kernel prepares request-local images before budgeting; the provider sends `image_url` parts only after complete tool-result batches. A short synchronous dispatch lease shares the store's revocation lock and rechecks the live scope, route, expiry and snapshot before starting HTTP. Historical execution projection never restores image authority. Diagnostics contain timestamp, hashed correlation, stage and safe error code only.

Image support is a closed allow-list: official OpenAI `/v1` with `gpt-4.1-mini` or `gpt-4.1-mini-2025-04-14` ([model documentation](https://developers.openai.com/api/docs/models/gpt-4.1-mini)), official DeepSeek root or `/v1` with the exact API model `deepseek-flash` ([vision documentation](https://api-docs.deepseek.com/guides/vision/)), and the exact existing local Buddy subscription tuple: provider `custom-openai-compatible`, base URL `http://127.0.0.1:8326/v1`, model `buddy/deepseek-v4.1-flash`. Its HTTP target is `/v1/chat/completions`; the disclosed recipient is Tencent CodeBuddy CN through local Buddy. Different providers, hosts, ports, paths, query strings and similar model names remain unsupported. This capability declaration does not authenticate a local service or replace existing credentials. No model configuration or credential is changed automatically.

Buddy may save attachments to disk and re-encode them, retry upstream requests or switch accounts. A native run can use multiple model requests; the application has no shared upstream attempt cap for this service. Stop or HTTP timeout cancels the application's request and revokes future image access, but does not guarantee that Buddy or the upstream stops, delete their copies or recall images already transmitted. The separate bounded test adapter does not change these production-service policies. Official-route requests retain low-detail selection; Buddy controls its own image processing and does not preserve the detail field. Small text and fine visual details may be missed. Metadata-based EXIF orientation and color-profile interpretation are not preserved. The existing 8,192-token image reserve, plus text and protocol overhead, remains in place; exact provider usage wins when available. The optional text-only local reference counter is bypassed for images. Provider transport fixtures establish serialization; UI-to-running-service semantic acceptance is separate.

Validation includes Agent image authority/envelope/model-turn tests, Infrastructure `SelectedImageProviderTests`, App `ImageToolsPluginTests` and Windows `SelectedImageDecoderTests` / `ChatImageSelectionTests`. Windows picker/decoder execution and real-provider visual interpretation require separate target-environment acceptance.

### Bounded P5 action confirmation

Only the registered `reminders` owner's `reminder.create` / `reminder.cancel` and `firstparty.focus` owner's `focus.resume` are eligible for this approval UI. Other Command tools remain denied. A supported wait projects the owner-frozen tool name, complete canonical arguments, business summary, object/resource identifiers and revisions, and exact expiry. Reminder summaries must exist and include the complete reminder text, local offset time, UTC time and time zone; cancel includes the precise reminder ID/revision. Focus resumption shows the frozen session resource and arguments without inventing current phase or remaining-time claims.

The Web bridge has no Allow/decision or mutable-argument field. Both presentations lead with a host title and the exact frozen business summary, or host formatting of the frozen Focus resource. Complete canonical arguments and versions remain under details; missing summaries expand the full details as a fallback. The front end does not infer action summaries from JSON or ask a model to rewrite them. `chat.approval.review` only opens an owner-bound native modal containing all details in a read-only scrolling text control. Its three explicit choices are Allow once, Deny (the focused/default choice), and Cancel task; closing is cancellation. Web `deny` and `cancel` can only refuse/cancel, never grant authority. Both presentations render data as inert text. Unavailable native hosts fail closed. Approval expiry comes from the broker (production five minutes), not from the browser clock.

The conversation owner checks live role/project/conversation scope, generation, run/request/revision and expiry before review and again after the native result. A single-review guard, the existing one-time checkpoint and the final business/resource validation reject replay or changed operations. Stop, expiry, role/project/conversation changes, a disposed Web surface and hiding/disposing the native host invalidate an in-flight native decision. Cancelling an ordinary Web surface does not itself execute or approve the pending operation. No tool parameters or reminder content are added to diagnostic logs.

`NativeConversationIntegrationTests.Approvals`, `ChatApprovalCommandReaderTests`, `ChatWebSessionTests` and `NativeApprovalDialogTests` cover the boundaries; `tests/chat_approval_probe.cjs` exercises production JavaScript with a synthetic host and is not evidence of a human/native decision. Windows/WPF/WebView2 execution remains a separate target-platform verification gate; a Linux cross-build or source-level test is not Windows acceptance.
