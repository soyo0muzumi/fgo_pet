# Understanding

Owns derived interpretations, candidate revisions, exact-version local review, lifecycle, idempotent receipts and metadata-only attempt/coverage state. Original conversation messages belong to Dialogue and confirmed user facts belong to Memory. User-fact proposals return `UNDERSTANDING_MEMORY_OWNER_REQUIRED`; stable identity and permission changes return `UNDERSTANDING_DEFINITION_FLOW_REQUIRED`.

`Core/Contracts` publishes the reader and host-side review DTOs. `UnderstandingService` uses the shared runtime database and module migrations, validating source snapshots through Kernel's owner port. Receipt lookup precedes fresh validation. A connection data-version check and immediate write transaction reject intervening source commits without reading Dialogue private tables. A batch validates all dependencies before persisting anything.

The default mode is OFF with source access, external processing, saving and conversation use all ungranted. OFF previews are available for ten minutes in memory, pruned on subsequent owner access or session close; explicit exact-version approval can save a preview. Policy changes invalidate previews and candidate revisions. Unreviewed bounded entries stop on mode/grant changes and do not reactivate automatically; those changes preserve retracted/resolved lifecycle states. Self entries expire after seven days; authorized exact historical reads preserve their original time and dormant state. Approval preserves evidence strength. Routing requires review unless separate, bound semantic classification and structural checks both permit the limited BOUNDED path. Model classification is evidence for this routing, not human acceptance or general semantic correctness.

`UnderstandingReviewScheduler` and `UnderstandingReviewService` are registered by Desktop. The default `IReviewBudgetAccess` returns no grant, so mode/grant changes alone cannot send a model request. A trusted host must bind an approved trial scope and the separate `ReviewCallLedger`. The ledger commits task/batch/trial precharges at the final HTTP handoff; failed, cancelled and unknown attempts never refund quota. It is independent of chat export, forgetting and restored backups. Unsupported or corrupt ledger stores fail closed.

Events only mark activity. Dialogue's bounded metadata scan and Understanding's transactional cursor/queue recover missed notifications without storing original bodies in work records. Queue pressure retains the scan frontier. Long originals advance by actual Unicode-scalar coverage; mixed item outcomes stay in receipts. Recovery checks committed receipts before renewed input, permissions or retries. OFF starts no automatic work, and new automatic grants exclude earlier ranges through `auto_since`. A manual preview's display acknowledgement is explicit; a returned result alone does not mark its attempt as displayed. Process interruption never automatically replays an OFF preview.

The scheduler uses monotonic idle/age measurements, six completed turns or an approximate 6k-token threshold. A separate one-minute background task bound leaves existing foreground/provider timeouts unchanged. Dialogue foreground leases preempt background work; maintenance cancels and drains it. Model calls run outside UI/commit transactions. A short owner transaction rechecks source, policy, input and target generations through synchronous HTTP handoff; the network await occurs after that transaction releases.

Asynchronous scheduler disposal cancels and drains both periodic work and explicit pulses, including a pulse made before periodic startup. Stopped instances cannot dispatch again. Cancellation keeps unfinished source ranges and the separate dispatch charge available for safe recovery.

`IReviewModel` and `UnderstandingReviewModel` implement the candidate protocol over Kernel's provider, request meter and stream aggregator. Schema 2 binds original aliases, exact selected target revisions and a request fingerprint; source coverage retains the host-supplied slice. No tools are offered. The adapter enforces the trusted host's `ReviewRequestLimits` and valid terminal usage; absent an explicit override, the existing 16,000 input / 2,048 output limits apply. Foreground dispatch, review and semantic classification share that bound capacity. Partial, malformed or stale results never become candidates. It identifies the request as the `understanding_review` auxiliary purpose so the Dialogue wire owner can apply its endpoint-specific JSON policy. The host still owns source reads, current permissions, atomic dispatch handoff, durable accounting, scheduling and the subsequent owner commit. Constructing this adapter or supplying capacity does not enable a worker or grant external processing. The existing v4 ledger retains its immutable call ceilings; an explicitly authorized host may supply a different `IReviewCallBudget` without changing those historical approvals.

The review template exposes the same owner restrictions as commit validation: assistant-only roots support only dated Self interests/stances; UserFact belongs to Memory, and identity/permission use their dedicated flows. Unsupported material must be omitted rather than renamed to pass a boundary. Self and World use the canonical subjects `assistant` and `world`; an observed object's name remains in content. These instructions do not replace the owner checks or independent semantic classification.

`ReviewBudgetedChatProvider` publishes its task input ceiling through Kernel's `IChatInputLimit`, so ordinary/Native composition sees the same 16,000-token allowance as the final handoff. Provider capacity, output reservation, original timeout and tool/Persona contracts remain unchanged. Optional records stay whole or are omitted; mandatory over-cap envelopes fail closed. A Self/World label cannot automatically replace an existing User/Relationship target.

Source revisions and read coverage are separate. The Dialogue authority validates a monotonic source revision in addition to the original fingerprint, preventing a completed/failed/completed transition from reviving an old reference. Host tickets bind source-version/scalar-range coverage independently of model proposals. Validation never upgrades unknown or partial coverage to a full read. Unattested coverage stays pending even when a test routing policy otherwise allows the content.

Automatic attempt reservations require candidate-saving permission and at least one attested source revision after the host's `auto_since` boundary. The boundary is captured on OFF-to-PROPOSALS/BOUNDED changes and when a non-OFF mode receives or regains read permission. Other grant changes retain the existing boundary. Earlier authorized sources can accompany the new range as background; an old-only range or missing save grant reserves no attempt. Explicit manual ranges retain their independent read/model authorization and need not enable automatic accumulation or candidate saving.

`UnderstandingPlugin` provides ordinary prompt data, Native context and `understanding.query` over the same effective-state reader. Pending/rejected entries are excluded. Unauthorized, disabled, changed-source and unavailable outcomes are distinguished. Context entries include conditions, lifecycle, source and correction together and are retained or omitted whole. No write tool is registered.

`Desktop` owns one content-first Settings entry with Saved, To review and Archived views. Saved is distinct from the current reply projection. Correct opens an in-memory draft and changes only the correction; pending entries still require exact-version approval. Forget confirms deletion of the entry and revision history while preserving original messages. Source coverage and recent versions are available on demand. Drafts survive page navigation and refresh within the WebView lifetime; changed scope/version bindings require explicit review before saving.

The host supplies readable role/project names, non-secret model recipient metadata and the current reply projection. Page context tokens bind mutations to the active scope, dialogue generation and policy generation, in addition to owner revisions. Valid mutations suspend/drain dialogue and recheck scope and cancellation before committing. Point-of-use local review consent, conversation-use consent, pause and revocation preserve existing independent permissions unless explicitly changed. The default host has no automatic review budget; opening the page neither enables automatic accumulation nor sends a model request. No editable OFF/PROPOSALS/BOUNDED or five-toggle setup is presented.

Privacy operations enter through Kernel's `IDerivedConversationData`: explicit export, forgetting a conversation/all derived data, and sanitizing an already-validated staged backup. Forgetting removes payloads and revision history, retaining only hashed revocations to prevent restoration from old backups. Restores merge current revocations, preserve retracted/resolved states from either the backup or current entries, reset all grants to OFF and mark other surviving entries dormant. Retracted entries cannot be approved, restored, suspended or resolved; correction/deletion retain their existing rules. No current database is normalized in place. The host owns maintenance and rollback.
