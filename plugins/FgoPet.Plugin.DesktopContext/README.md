# Desktop Context Plugin

Small read-only observations for ordinary conversation background and the Native tool loop. It depends only on Extensibility; it owns no conversation history, memory, tasks, background polling or model connection.

`context.time` samples the host clock once and returns UTC sampling time, local date/time, time zone ID, offset and daylight-saving status. The host validates the current conversation/role/project around the observation. Old conversation timestamps are not a substitute for a current sample. The production host registers this tool.

The plugin also contributes a fresh clock as a whole data block through `IConversationPromptProvider` and `IAgentContextProvider`, including when ordinary conversation has no tools. The optional `contextSnapshot` callback supplies a host-owned `CompanionContextSnapshot` for the exact role/conversation/project scope. It must read cached observations without performing Windows discovery or model/network work during prompt assembly. Internal activity can be supplied by its owner; private application/window facts still require their separate live source permission. This callback does not obtain or widen any permission and does not use the one-message Chat window selection.

Background observations carry source ID/version, observation time, expiry, and their interpretation flag. The host's revision changes with meaningful state or source permission changes, rather than each read. The plugin samples the owner twice and discards changed scope, revision, source version or content; failed observation reads leave the clock available. Expired/future observations, invalid metadata, duplicate source IDs and oversized entries are omitted. It examines at most 32 observations and projects at most eight, with 6,000 characters per original content and 8,000 serialized characters in total. Both conversation paths preserve each projected record whole under prompt budgeting. All blocks are data, never trusted instructions; an interpretation is labeled tentative and is not promoted to an observed fact.

The host remains responsible for source sampling, permission ownership, cancellation on revocation and in-flight request invalidation. The callback is not a continuing-read grant. Scope changes and plugin stop/disposal prevent further context projection; raw observations are not persisted by this plugin. Reading current background does not create a user message or an autonomous model request.

`context.apps` is registered only when a trusted caller supplies both a revocable scope authorization callback and an application reader. The production host supplies these ports, but application discovery stays disabled until the user explicitly saves application-overview approval in Settings → App → Understanding → Ambient awareness. Approval binds the active scope and configured model; changing the model requires saving again. Model arguments cannot supply or enable either port. The plugin creates no persistent grant or settings entry. Revocation during observation discards the result.

The App host samples background sources every 15 seconds with a two-minute observation lifetime. Focus/reminder summaries and the shared local Todo book default on; the task book is shared across roles and projects, and the clock does not depend on that option. Application overview defaults off and contains only application names, foreground status and window counts. Window text uses a separate session-only grant: explicit enumeration shows titles, and choosing a native source token allows repeated reads of that same window until scope/model/title changes, closure or revocation. Choosing another window replaces the old permission. Source sampling itself does not invoke a model.

The host can separately enable bounded background judgments without a new user message; that option defaults off. The independent allowance is six calls per rolling 24 hours, adjustable to 1–24, with a five-minute minimum dispatch interval within one app session, at most one model request per activity, 4,096 input / 384 output tokens and no tools. This does not publish unsolicited dialogue or modify long-term Understanding. A temporary result is available through the same context callback only while its captured source context remains current. The model budget can shorten or omit sources; source identity and observation metadata do not prove full read coverage. Kernel owns this activity protocol, and the App host owns its consent and accounting.

`WindowsApplicationDiscovery` can enumerate visible, non-cloaked top-level windows in the current desktop and group them by executable stem. It excludes the desktop shell, bounds enumeration to 512 windows and checks a two-second scan deadline, and returns at most 32 applications. Results carry start/end sampling times, partial-coverage status and whether the sampled foreground window was represented. Protected, disappearing or unsupported windows may be unavailable; process existence alone does not count as an open application. The deadline is checked between synchronous Windows queries, not a hard process timeout.

No window titles, command lines, executable paths, text bodies, screenshots, keystrokes or browser profile data are collected by the application-overview adapter. Discovery does not establish that an application's content can be read; selected-window text comes from the host's separately authorized window reader. Names are untrusted observation data and may not be user-facing application names.

Diagnostics contain only timestamp, hashed invocation correlation, phase and safe error code. No application observations or tool arguments are logged.

Validation: run `FgoPet.Capability.Tests` filtered to `DesktopContext` and `FgoPet.App.Tests` filtered to `DesktopContextWindowTests|NativeConversationIntegrationTests|ServiceRegistrationTests`. Fixtures cover bounded observations and revocation; the Win32 check queries only the test's own hidden window handle. Synthetic Native model tests and that controlled handle check do not establish real desktop-model acceptance or full desktop discovery coverage.
