# Built-in Skills

This plugin provides seven static instruction packs through the native `ISkillProvider` contract: `daily-planning`, `todo-maintenance`, `task-capture`, `focus-session`, `document-review`, `web-lookup`, and `daily-report`. Each descriptor has a fixed version and a SHA-256 digest computed from its UTF-8 instruction body. The bodies are embedded in the plugin; loading a skill does not read external files, execute code, or contact a service.

The skill instructions explain how to use existing capabilities. They do not perform tool calls, grant permission, or replace the capability owner's validation. `SkillRegistry` requires each declared required tool to have an active registration before exposing or loading that skill; this does not prove that a particular call has current authorization or valid settings. Optional tools can be absent; the body tells the agent to describe the resulting limits. `daily-report` intentionally has no required tools so it can draft a report from user-provided information when Todo, Memory, or Workspace tools are unavailable.

General Native approval, retry and idempotency rules are maintained in the Kernel's `NativeAgentEnvironment.CorePrompt`. Skill bodies keep workflow-specific instructions, source coverage, business confirmation and tool-specific recovery limits. Version `1.0.4` removes repeated general permission prose while preserving these owner requirements; content digests still bind each loaded body.

`task-capture` requires `submit_todo_proposals` for the current conversation's pending draft; a successful proposal result does not confirm saved tasks. Direct `todo.create` execution is optional and still requires policy approval and exact owner business confirmation. `focus-session` describes the current get/start/pause/stop surface; resuming a paused session is unavailable through those Native tools.

Todo changes and Focus commands remain under their existing owners and require applicable policy approval and business confirmation. Document review must cite extracted source evidence and disclose truncation or unread portions. Reports must distinguish drafts from confirmed tool results, and must not claim a task changed, a session ran, or a document was saved until the owning tool confirms that outcome.

`web-lookup` adapts the bounded search and primary-source verification guidance from Tavily's MIT-licensed search skill at revision `778122e5f9c680f541eeceda5a5b36405eb7980c`; attribution is in `THIRD-PARTY-NOTICES.md`. It requires `web.search`, with optional `browser.open`, `browser.read` and `browser.tabs`. Failed or incomplete opens require verification of existing tabs before another open; when that verification is unavailable, the workflow reports the limit instead of blindly opening again. Upstream CLI, installation, login, crawl and research execution instructions are not imported. The host still owns authorization and execution; a search snippet or snapshot hash does not establish full-page reading or an original website revision.

The host registers this plugin through the standard `IFgoPetPlugin` catalog. Tests for the descriptors, content hashes, required-tool gate, and optional-tool behavior live in `tests/FgoPet.Capability.Tests/Skills`.
